# 下一轮 Windows／Linux 适配清单

本轮只验收 macOS ARM64。下表区分已接入的共用边界与下一轮必须在目标系统完成的工作；接口、单元检查和编译结果均不代表安装产品已支持。

| 边界 | 当前实现 | 下一轮门槛 |
|---|---|---|
| 原生程序与资源定位 | `@captraw/desktop-core/engine` 集中处理可执行文件后缀；桌面资源用 Node 路径 API 拼接 | Windows EXE／DLL、Linux ELF／共享库及资源目录从安装包离线启动；不依赖开发机器路径 |
| 缓存及协议路径 | 相对路径判定替代 POSIX 前缀；文件 URL 用标准转换 | 验证盘符、UNC、中文／空格、大小写、路径长度和过期预览；拒绝跨缓存目录读取 |
| 编辑与资产 | XMP 源关联使用旁车相对路径及 `/`；资产使用 SHA；平台文件版本只存会话快照 | 在两平台分别验证整个项目目录移动、另存、资产丢失、只读目录及跨系统移动；原生源身份读取当前使用窄字符串文件流，Windows 须统一 UTF-8 到系统路径的转换，并验证中文、长路径、UNC 与 Node 计算的 SHA 一致；原片不回写 |
| 原子发布 | 临时文件位于目标卷；macOS 原生排他发布使用 `renamex_np` | Windows／Linux 实现并验证排他发布和已有文件替换；当前非 Apple 硬链接路径不能代替对 FAT／网络卷的验收 |
| 任务取消 | Node 子进程终止集中处理，清理等待进程结束 | 目标系统实测解码、蒙版求解、导出、XMP 超时及退出；检查子进程、句柄和临时目录均释放 |
| 构建与依赖 | Homebrew、Mach-O、macOS SDK 与 OpenMP 参数限在明确拒绝其他平台的构建／打包入口 | 提供独立工具链适配及固定依赖／许可；核实 ART、LibRaw、LittleCMS、GTK 相关依赖、XMPFiles 和已有编码器；不提供空实现 |
| XMP 运行库 | 固定 SDK 的照片 handler；文件和扩展 JPEG 的空节点保留补丁有散列记录 | 正确选择平台宏、Host IO、线程和系统 XML 库；重跑限定符、多语言、扩展 JPEG、隐私及文件移动检查 |
| 输入及交互 | 业务编辑命令、不可变目标与相对旋转共用；文件对话框留在 Electron 边界 | 目标系统实测主修饰键、原生文本剪贴板、菜单、拖放、焦点、IME、鼠标捕获及最小窗口 |
| SDR 显示 | 后端输出声明正确的 Display P3 半浮点帧，受管理 Canvas 交给 macOS 完成显示设备转换；不支持时明确回退 sRGB | 多显示器、缩放／DPI、ICC、Windows 显示设置及 Linux X11／Wayland 分别验证；编译成功不能证明颜色正确 |
| 安装与更新 | 当前打包、签名和部署流程针对 macOS | 各平台建立安装、卸载、离线依赖和用户数据保留流程，提供对应源码与许可；签名、权限和沙箱单列 |

两平台各自从安装包回放同一任务：导入多图、筛选／评分／色标、联动调节、局部和修复、预设／同步、保存重开、批量导出、完成／取消。还须覆盖隐藏活动图、处理中切图、原片被替换、取消、部分失败及磁盘错误。

RAW 解码按机型与压缩模式复验，包含当前 Nikon HE／HE★ 样本；不能由 macOS 结果推及其他编译器。Linux 使用固定 ACR 参考文件对照，不设虚构的 Linux ACR 运行基线。性能和长时间稳定性在可比硬件上独立记录，隐藏 E2E 与人工可见任务分开。
