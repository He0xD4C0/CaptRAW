# 本地核心协议

核心库目标为 `captraw-core`，进程为 `captraw-engine <resources-directory> <private-cache-directory>`。它没有 Electron 或窗口初始化依赖。CPU / OpenMP，Vulkan、SIMDE、OCIO、CTL、mimalloc 后端关闭；固定 ART 接口由 CMake 编译验证。

stdin / stdout 每行一个 JSON 对象；ART 自身 stdout 重定向到 stderr，保证控制输出纯净。请求 `{ "id": 1, "method": "open", "params": { ... } }`，结果 `{ "id": 1, "result": ... }` 或 `{ "id": 1, "error": "..." }`；异步帧和进度使用 `event`。启动发送 `ready`。公共类型见 `packages/contracts/index.ts`。

| 操作 | 参数 | 结果 |
|---|---|---|
| `open` | 绝对 `path`、不重复的 `sessionId`；`baselineVersion` 如提供只能为 4 | 可用图像尺寸、相机、ISO、实际 `inputProfiles` 能力、默认控件投影、完整 `artProfile`、相机构图 `cameraCrop` 及固定基线 4 |
| `adjustmentBase` | 完整 `artProfile`、`groups: (hsl / parametricCurve / colorGrading / calibration)[]` | 只读投影稀疏 XMP 所需的原生基值，不读取图像或更改会话；无法无损投影时拒绝 |
| `whiteBalance` | `mode: camera/auto/preset/sample`；可选 preset ID 或原始图像归一化坐标、奇数像素窗口 | 返回精确相机通道系数、色温 / 色调投影和显示状态，不直接更改当前配方 |
| `maskAssets` | 完整 `artProfile`、可选控件投影 `adjustments`、精确路径 `replacements`、`validate` | 递归枚举 / 重绑定四种工具中全部外部蒙版路径，包含停用工具与组件；可解码核验。同时处理投影中的栅格引用（含停用组件）；返回完整配置及传入的投影，不修改当前图像 |
| `validate` | 完整 `artProfile` 和 `adjustments` | 无图像解码的配方参数检查、输入配置 / 黑白 / 分级投影，以及按来源配置绑定参考角的 `masks`；不改变已打开图片 |
| `update` | 递增 `revision`、`adjustments`、可选 `artProfile` 和仅控制显示的 `maskId` | 更新后的完整 ART 配置文本；异步输出 fit 帧 |
| `viewport` | `revision`、`x/y/width/height`（已旋转图像像素坐标） | 真正 skip=1 的 detail 帧，按原图边界限制请求范围 |
| `coordinates`（未发布） | `sessionId`、当前 `revision`、`from/to: display/reference/source`、1–4096 个 `points`，可选 ±45° `referenceAngle` | 完整粗旋转画布的像素中心坐标映射；不含裁切偏移或归一化。保留图像外坐标，逆解失败的点返回 null；拒绝过期会话 / revision，不更改配方 |
| `before` | `revision` | 初始显影 before 帧，不更改保存配方 |
| `curve` | 有序 `points` | ART 实际样条采样，用于前后端一致性检查 |
| `save` | 无 | 核心当前完整 ART 配置文本，文件事务由宿主负责 |
| `export` | `path`、完整 `artProfile`、`output`、`format: jpeg/tiff`，可选 `colorSpace` | 全分辨率处理；TIFF 为 uint16，JPEG 95，嵌入输出 ICC；返回 path / outputProfile |
| `cancel` / `close` | 无 | 停止预览 / 释放当前图像 |

每个进程持有一个活跃图像；多图文档由宿主管理并在切换时重新连接。导出使用独立进程和配方快照，取消由宿主终止该任务进程；常驻核心的同步控制队列不能中断同进程内正在执行的全图导出。退出或崩溃不能损坏原片或保存配方。

预览帧包括 revision、会话、完整尺寸、区域坐标、三通道 256 档真实输出直方图、私有 PNG 文件路径及耗时；可选 `mask` 包含组 ID、覆盖图及其图像坐标范围。每帧文件名唯一，PNG 写入 sRGB chunk。宿主只将自己的缓存路径映射成 `captraw://preview/` URL，保留有限帧；没有 Base64 图像控制消息。前端丢弃过期会话和 revision，连续调整延迟 90 ms 合并。Canvas2D 按 sRGB 解码，1:1 使用 `1/devicePixelRatio` 的 CSS 缩放；不重复执行后端色彩变换。

`EditDocument` 是 XMP 的内存投影，包含固定引擎版本、源路径 / 大小 / SHA-256、完整 ART 配置和控件值。当前核心写入引擎 26，读取 20–26；不恢复旧 JSON、基线 2 / 3 或其他处理版本。`adjustments` 由 C++ 适配器映射，渲染与输出读取完整 ART `ProcParams`。XMP 保存先写旁侧临时文件，再原子 rename；导出成功后才替换目标。以下带历史版本的实现记录不构成旧文件格式兼容承诺；当前文件协议见末尾 XMP 章节。

引擎 14 的颜色分级使用 `adjustments.colorGrading`：`shadows/midtones/highlights/global` 各有 `hue:0..360`、`saturation:0..100`、`luminance:-100..100`，外加 `blending:0..100`、`balance:-100..100`。`validate` 返回同名投影；完整原生参数保存在 `[CaptRAW Color Grading]` 的 `Version=1` / `Values`，顺序为四组三值、混合、平衡。缺省可继承完整配置，显式初始值清除该组；原生加载拒绝版本、长度、范围和有限值错误。共享 Stage 3 在黑白之后处理，全中性旁路，继承参数变化同样刷新预览缓存。详见 [接入与限制](COLOR-GRADING.md)。0.17 已接入 Web 色轮；数值不等于 Adobe 参数。

蒙版与裁切以原始可用图像的归一化坐标保存；EXIF 原始传感器边界不是可用图像边界。90° 旋转在适配器内映射到 ART 图像坐标。画笔 radius 遵循 ART DrawnMask 半径单位：`radius × 0.1 × min(width,height)`；擦除顺序保存在同一笔迹序列。局部亮度以 `2^value` 映射 RGB slope，局部对比度映射 RGB power，局部饱和度使用区域 outSaturation。全局 tint 为 `100 × ln(ART green)`，不冒充 ACR 色偏单位。RGB 与三个颜色通道曲线使用 ART 自然三次样条，支持 2–128 个有序点；Web 图形密集采样同一算法，实际处理由 ART 完成。0.2 新增的高光 / 阴影 / 白色 / 黑色接入 ART ToneEqualizer，锐化使用 USM，降噪使用传统 RGB 方法，HSL 接入 ART hue 曲线，去朦胧、颗粒、晕影、Lensfun 均走原处理模块；它们不是 ACR 同名算法或相同数值单位。

资源生命周期：加载所得 InitialImage 保留一个宿主引用；交给 StagedImageProcessor 前增加一个引用，由处理器销毁时释放。关闭先等待处理结束、移除监听器、销毁处理器，再释放宿主引用。detail 属于处理器，回调图像只在回调期间有效，必须当场编码。

蒙版组的 `components` 按顺序包含 `add/subtract/intersect`。覆盖率从 0 开始；添加为 max(a,b)，减去为 a×(1−b)，相交为 a×b；组反选和不透明度随后执行。各组件复用 ART 几何 / 画笔与羽化，组合后只执行一次该组的局部调整。未绘制组件不参加计算。`CaptRAWComponentCount` 和索引子字段随完整 ART 配置保存，独立进程读回；原版 ART 忽略扩展，不能用原版 ART 打开它来验证组效果。覆盖层直接读取 ART 完成组件组合、羽化、反选后用于局部处理的同一浮点覆盖率，量化成透明度 PNG；不是前端再次计算形状。适屏及详细区域各带覆盖图，前端避免两层重复叠加，并按图像范围和裁切裁剪。详细区域按有效羽化范围扩展邻域；只编码可见区域，不将邻域大图传入 Web。`maskId` 不保存到配方，也不参与导出；0.3 的处理版本与 0.2 相同。

0.4 的白平衡处理版本为 3。新照片基线使用相机原始系数，经 ART `wbMul2Camera` / `wbCamera2Mul` 坐标系转换后以 `WBParams::CUSTOM_MULT` 渲染，避免把系数压缩成色温再还原。`wbMultipliers`、`wbMode` 和投影警告由核心返回；手动色温 / 色调清空系数并使用原有 CUSTOM_TEMP。自动白平衡取 ART 估计，预设来自随包 `wbpresets.json`，只按相机内部完整型号匹配；采样调用 ART 原生 RAW / 图像取样，处理旋转和几何坐标。

`EditDocument.baselineVersion` 仅表示当前基线 4；宿主不再选择旧基线，核心拒绝 2 / 3 等不受支持的值。新照片默认值和重置使用相机白平衡及有效相机构图；XMP 打开与胶片切换保留各自编辑，对比前状态规则见文末。

0.5 接入输入配置文件，处理版本为 4，初始显影基线仍为 3。核心在 `open.inputProfiles` 返回实际相机匹配结果及 DCP 能力：自动选择按 ART 原有顺序优先 DCP、其次 ICC，再回退相机矩阵；显式矩阵不使用 DCP / ICC。嵌入选项仅在检测到 ICC 或 DNG 配置文件时提供；普通图像没有 RAW 相机矩阵选项。`adjustments.colorProfile` 映射选择、双光源插值及 DCP 内部曲线 / 表 / 基准曝光字段；控制是否显示取决于真实数据。切换触发 ART 原有颜色处理，Web 不实施配置文件变换。

旧配方缺少 `colorProfile` 时，预检查从其完整 ART 参数提取对应控件状态，避免新默认值覆盖旧引用。`inherited` 保留外部或特殊输入引用，供历史和保存恢复使用；0.34 已提供导入器和 XMP 随附资产，见文末接口。直接读入绝对路径引用时仍须提供对应文件。预检查、更新及导出拒绝缺失 / 无效的外部配置文件，避免 ART 静默回退到矩阵。随包相机配置按固定 ART 版本解析；DCP / ICC 不等于 Adobe 风格、配置文件数量或显影效果对齐。

打开配方先验证参数与基线版本，再替换当前核心图像。若显式打开的配方指向已打开且有未保存编辑的原片，则保留当前编辑并提示先保存或关闭；直接切换会话图片不触发此保护，也不会丢失未保存配方。白平衡异步计算期间若文档或调整已改变，丢弃旧计算结果。

ART 兼容性修正：白平衡 Multipliers 的保存类型和字段为 double，但原载入代码使用 float 中转；现按 double 载入，避免新精确白平衡配方重开后损失精度。X-Trans 三遍插值原先在尾块扩大 mrow/mcol，超过已初始化的同质性范围；现保持有效范围并用现有 11 像素边缘插值补齐。生产代码不清零 / 填充缓冲区来掩盖越界读。该缺陷修正会改变历史 X-Trans 边缘输出；旧基线的白平衡语义仍保持，不能承诺保留未初始化数据产生的旧像素。

0.6 的处理版本为 5。`adjustments.blackWhite` 保存开关、八个整数混色值及原生黑白转换的基础参数投影（原有 RGB 权重、预设、滤镜、gamma 与色调）。旧配方从完整 ART 参数恢复这些值，避免迁移时强行换成新默认值。黑白混色独立保存为 `Black & White.CaptRAWLuminanceCurve`；中性曲线不新增 ARP 字段，彩色默认参数与 0.5 保持一致。

八色中心由 sRGB 参考颜色转换到当前工作色域，再按 ART 的 YUV 色相定位；不是把 HSV 坐标直接当作 ART 色相。处理在原有黑白转换前复用 HSL 明亮度计算，以 `min(1, chroma / luminance)` 减弱近中性色响应，原彩色 HSL 不启用此加权分支。这样避免灰色残余色相导致的变化；该扩展不等于 Adobe 黑白算法。完整 ARP 可交给本项目的独立核心或含相同补丁的 ART CLI；原版 ART 不识别新字段。

## 取样修复与仿制

`adjustments.spots` 顺序保存 ID、名称、开关、原始可用图像归一化来源 / 目标，以及 method、radius、feather、opacity、detail、retainTexture。radius 为原图像素，范围 2–200；羽化 / 不透明度为 0–100，映射 ART 的 0–1；羽化外半径为 radius × (1 + feather / 100)。clone 对应 ART detail 0，保留目标细节对应 1；heal 对应 2–5（界面精细度 0–3）。这些是 ART 语义。

C++ 将坐标旋转到 ART 完整图像像素坐标，再写入原生 Spot Removal；局部裁切不改变来源 / 目标关联，来源可以位于详细预览之外。停用点保留在编辑文档中，处理列表只包含启用点。XMP 直接恢复完整 spots 参数；旧 ARP 修复点反投影和 `recipeSpots` 返回值已移除。初始显影保持无修复，更新和导出继续验证现有修复参数。

ART 的 Laplace 修复迭代原来以 OpenMP 同时更新相邻行，造成读写竞争。补丁仅移除该迭代内的行并行，保留原有更新顺序和其他独立计算的并行；因此与旧单线程结果一致，而旧多线程修复像素可能改变。测试比较 1 / 2 / 8 线程、独立进程及带相同补丁的 ART CLI。连续修复画笔和自动选源未实现。

## 蒙版局部细节

0.8 处理版本为 7，`LocalMask.details` 为可选投影；缺失或中性值不改变旧蒙版的完整原生参数。hue 映射独立的 YUV 色相区域（-180–180 度）；texture 与 clarity 映射 TextureBoost.strength=value/50，detailThreshold 分别为原生默认 0.2 和较大尺度 4；noise 映射亮度通道 NLMeans 强度 0–100，noiseDetail 映射其细节保留参数。高感质量、肤色和 ACR 对照尚未验收。

原生纹理 / 平滑区域的 MaskName 使用 `@CaptRAW-details-v1:` 标记所有权、原模块启用状态和蒙版 ID。每次更新仅移除标记区域、恢复原启用状态，再从当前文档重建；其他原生区域保留。停用但非中性的独立原生参数不能随新增区域自动启用，因此明确拒绝该合并；原配方保持可恢复。零值、停用、删除、复制后删除和撤销均验证无残留。

纹理增强具有全图最小值约束；NLMeans 也有区域相关的细节估计。含新局部细节的 1:1 不能只给固定邻域：核心请求全图 skip=1 处理，回调只编码所需视口（仍最多 2048×2048）。缓存最终 RGB8 和当前组浮点覆盖率；后续 viewport revision 仅从缓存裁取，覆盖图同步更新。参数 / 显示蒙版改变、初始状态对比、打开或关闭图像时失效和释放。滤镜计算、色彩与 TIFF16 仍走原生高精度管线；RGB8 缓存只用于屏幕预览。此路径首帧和内存成本明显高于普通裁块，尚未完成全部设备与大图性能验收。

0.9 的处理版本为 8，新的初始基线为 4。`RawImage` 在 LibRaw 解码缓冲释放前复制 Nikon `raw_inset_crops[0]`，随后按实际活动区边距、ART 去马赛克边界及 EXIF 方向映射为 `cameraCrop`。只保存四个整数，不延长解码缓冲生命周期。核心仍返回原有可用图像坐标和尺寸；默认裁切是同一 ART 配方里的 crop，并非改写解码结果。其他品牌及无有效裁切标签的输入不新增默认裁切。

当前文档统一使用基线 4，相机构图按钮仅在核心提供有效数据时显示；裁切、局部蒙版及修复仍使用原有坐标空间。

`CAPTRAW_E2E_BACKGROUND=1` 只用于后台测试：BrowserWindow 从创建时隐藏且不可聚焦，关闭后台节流以继续绘图；macOS 使用 accessory 激活策略。生产正常启动不设置该环境变量。E2E 共享启动器验证 `isVisible=false`、`isFocused=false`、`isFocusable=false`，旧包没有该开关则在启动前拒绝测试，避免闪现窗口。


## 蒙版局部白平衡

0.10 引入此处理，当前初始基线为 4。`LocalMask.whiteBalance` 可选，包含 -100–100 的 temperature / tint；未设置或均为零时不保存矩阵，也不进入新处理分支。

温度映射 `6504 × 2^(temperature/100)`，绿通道参数映射 `exp(-tint/200)`。ART ColorTemp 估计光源，LittleCMS `cmsAdaptToIlluminant` 在 XYZ 中执行 Bradford 适应；通过当前工作 RGB 的正逆矩阵形成完整 3×3 变换。正色温趋暖，正色调趋洋红。矩阵在原有 ColorCorrection RGB 区域处理前作用于线性像素，同一组覆盖率只应用一次。它不改变全局 RAW 白平衡、不进行第二次去马赛克，不声称与 Adobe 参数等效。

完整 ARP 保存 `ColorCorrection.CaptRAWWhiteBalanceMatrix_<region>`，仅接受九个有限且绝对值不超过 64 的值。原版 ART 不识别扩展；独立导出及参考 CLI 均需本项目补丁。局部白平衡本身不增加全图上下文缓存，沿用区域处理；受控样本的 ROI 与全图 RGB8 最大差为 1，完整 detail 与 fit 同分辨率图像一致。TIFF16、独立核心及补丁 ART CLI 逐像素一致。混合光源、肤色、极端颜色和 ACR 画质盲评仍待完成。


## 蒙版局部明暗

0.11 处理版本为 10，基线仍为 4；旧版本及显式基线保留。`LocalMask.tone` 可选，保存 -100–100 的 highlights / shadows / whites / blacks；映射为原生整数频段 `[blacks, shadows, 0, highlights, whites]`。均为零时删除扩展字段并完全跳过新分支。完整 ARP 使用 `ColorCorrection.CaptRAWToneBands_<region>`，载入检查五个整数和范围。

复用 `iptoneequalizer.cc` 的同一计算函数，保留 ART 默认 regularization=4、pivot=0、EV 分段和引导滤波。局部路径从当前线性 YUV 亮度计算增益，不复制算法到前端。存在有效局部明暗时按区域顺序处理：当前图像计算增益 → 该区域局部白平衡和 CDL → 原有蒙版覆盖混合；后续区域看到前面的结果。每次只保留一个增益平面；没有局部明暗时沿用原来的按行循环。原版 ART 不识别扩展，参考 CLI 需应用相同补丁。

局部明暗含较大引导滤波邻域，1:1 复用全图上下文缓存路径，防止裁块明暗不一致。受控样本的四项正负方向、组合和旋转均与全图同坐标一致；首次完整处理、参数变化后的重算仍有性能成本。没有把该算法和参数称为 Adobe 等效实现。

同时修正局部白平衡矩阵的载入：直接读取 double 数组，不再经过 ART 的曲线格式整理函数。合法矩阵首项恰为曲线类型编号时不得改写其余系数；接近同一 float 值的矩阵导出逐像素一致。尺寸、有限值及范围检查继续保留。


## 全局纹理与清晰度

0.12 处理版本为 11，初始基线仍为 4。`adjustments.texture` / `clarity` 为可选 -100–100 数值；缺失按零处理，不向旧配方投影强行添加字段。分别映射全覆盖 TextureBoost 区域，strength=value/50，detailThreshold 为 0.2 / 4；使用已有 `@CaptRAW-details-v1:` 所有权机制，标记为 `global:texture` / `global:clarity`。保留原生继承区域，随后添加全局区域和局部纹理区域；全局与局部独立复位，不是复制一层 Web 滤镜。

## 独立参数曲线（0.14 / 引擎 12）

`adjustments.parametricCurve` 保存四个 -100…100 明暗区域和三个 1…99 百分比分界；分界递增且间隔至少 1。缺失字段或全零时不执行额外处理，维持原有像素及原生参数文本。已有基线 2 / 3 / 4 不迁移；引擎 11 及更早配方继续读取，新配方标记引擎 12，避免旧版误读扩展。

原生 `parametricCurve` 控制消息返回 ART `DiagonalCurve` 的 513 点采样，Web 只绘图，异步结果按设置键丢弃过时值。不是另一份 JavaScript 曲线算法。全分辨率和适屏处理使用同一原生定义，经 ART 原有 `adjust` 转换至线性工作域，再通过标准 `ToneCurve` 应用；预览采样图展示其编码域定义，不是最终图像全管线的传递函数。

`ToneCurveParams::captrawParametric` 为独立字段，保存为 `[ToneCurve] CaptRAWParametric`，在两个原有曲线之后、饱和度曲线之前处理。使用原有 ART 参数曲线算法、范围转换和通道映射，没有覆盖 `curve2` 或改变继承曲线模式。仅非零值写扩展字段，身份曲线不走新分支。完整参数保存 / 读取、比较及缓存失效均包含此字段；补丁 ART CLI 可独立复现，原版 ART 不认识该字段。

曲线通道栏切换只改变编辑视图；参数曲线与点曲线同时生效。参数复位重置四区域和三个分界，点曲线保留。Radix 键盘的提交回调先于数值变化，统一在同轮微任务结束时提交历史，保证键盘操作不与下一次手势合并。定点工具、ACR 数值 / 色彩 / 画质等效验证未完成。


## 白平衡重载与高质量详细预览（0.15 / 引擎 13）

`White Balance/Multipliers` 必须直接用 `keyFile.get_double_list` 读取。ART 的通用 `vector<double>` 读取重载用于曲线，内部会调用 `sanitizeCurve`；此前为避免 float 精度损失而改用此重载，误将 RGB 系数当成曲线，独立导出重载时回退至 `[1,1,1]`。现在保留双精度且绕过曲线校验；补丁同时支持原始 ART 和旧版已打补丁源码。不是修改 RAW 解码器或套用前端色彩补偿。

更新参数时，精确通道系数变化也触发 `WHITEBALANCE`，即使色温 / 色调投影未变。第一次请求详细区域或参数变化使高质量状态失效时，采用 ART 原界面的 `getHighQualComputed → startProcessing(M_HIGHQUAL) → setHighQualComputed`；仅调用 crop 的 `fullUpdate` 会沿用适屏快速去马赛克和预处理。后续已有高质量状态的区域更新仍走原缓存。

同一 session / revision 的适屏刷新不会清除已经到达的 detail；不同会话或旧 revision 仍丢弃。完整上下文滤镜的缓存和取消机制不变。新配方标记引擎 13，读取引擎 12 及更早配方；基线 2 / 3 / 4 和已有调整坐标不变。修正作用于所有配方的重新导出，不保留错误的白平衡加载行为，所以旧版 TIFF 不能作为新版本的逐像素兼容目标。旧安装包保留用于历史复现。

`tests/preview-output.mjs` 覆盖相机 / 自动 / 预设 / 吸管 / 手动及仅系数变化、DCP / 矩阵、点与参数曲线、NEF / CR3 / X-Trans / Z5II HE 两模式；独立进程输出相同坐标 ROI。`tests/inspect-preview-output.py` 检查 uint16、ICC 和量化像素，再检查隐藏安装版旧配方 / 自动 / 手动白平衡的全尺寸 TIFF。不同 ART Camera / CustomMult 模式的原始 16 位差异另外记录，不将两种模式一概声称相同。


## 曲线输入直方图（0.16）

核心通过 ART `HistogramListener::histogramChanged` 读取 `histToneCurve`，不从最终 sRGB 像素反推输入。上游先按工作色域矩阵计算亮度、通过 `gamma2curve` 编码并压缩至 256 桶，再对高度执行原有 `xlin2log`。统计位置在 toneCurve 入口，包含上游处理但不包含本模块点曲线、参数曲线等操作；数据是适屏全图而非裁切框统计，各曲线通道当前共用明度背景。

ART 的 `imageReady` 在直方图通知之前调用。核心先标记待发布，等同次通知到达后把 `curveHistogram` 与 PNG、sessionId、revision 一起发布，沿用前端的旧 revision 丢弃规则。详细区域不覆盖这个全图输入分布；切图及关闭清除原帧。不要让上一轮统计配上下一轮图像。顶部 RGB 直方图继续统计输出预览，两个图各自表达不同处理阶段。

上游 `hist[y >> compression]++` 位于 OpenMP 并行循环内，多个线程写同一桶会丢计数。用原子增量修正，单线程与多线程所得 256 桶一致。此项只改变统计元数据，未变更显影像素、配方或默认参数，所以维持引擎 13 / 基线 4。前端按原生最大值归一化绘图，不额外对数压缩，不拦截鼠标事件。

## SDR 输出色域（0.18）

`export.colorSpace` 接受 `srgb` / `adobe-rgb` / `prophoto-rgb` / `display-p3` / `rec2020`，分别映射随包 `RTv4_sRGB` / `RTv4_Medium` / `RTv4_Large` / `RTv4_DisplayP3` / `RTv4_Rec2020`。只修改本次独立输出的 ProcParams 副本，采用相对色度和黑点补偿；显影配方、工作空间、预览与撤销历史不变。未传入时沿用完整原生配置的输出设置，保持既有无界面调用；桌面默认显式选择 sRGB。未知 ID / 格式在处理前拒绝，指定 ICC 缺失时失败，不静默使用替代色域。

## 亮度范围蒙版（0.19）

`MaskGeometry.type=luminance` 使用 `luminanceRange:[outerLow,innerLow,innerHigh,outerHigh]`，0–100，要求外侧顺序不交叉、内侧下限小于上限。默认 `[0,0,100,100]`。创建即生效，局部调整初始中性；无几何锚点。Web 提供四个滑杆节点和数值输入，拖动一步历史、Enter 提交 / Escape 取消数值，Shift+L 新建。0.20 补充照片取样和灰度亮度图，见下文。

核心映射到 ART `ParametricMask.lightness` 非周期 MinMax 控制点曲线，使用 ART 原生平滑过渡（切线 0.35）。范围依据色彩校正入口的工作 RGB 转换 Lab L*；不是最终 sRGB 像素亮度。关闭亮度细节及空间模糊（blur=-10），过渡由亮度范围自身决定；相等内外节点使用不超过 0.0001 L* 的数值过渡，避免原生曲线重复 X。完整范围使用 ART 默认恒定覆盖。

范围可出现在蒙版组的添加 / 减去 / 相交组件中。包含范围的组以内部唯一名关联后续 TextureBoost / Smoothing 选区，复用 ART LinkedMaskManager 的半精度覆盖缓存，避免前面的局部曝光使后续模块重新选择不同像素；组名仍由 JSON 保存并在 Web 显示。关联数据和曲线均写入完整 ART 配置，不依赖 Web 才能输出。几何蒙版沿用原处理，旧配方不插入范围字段。基线仍为 4，引擎升至 15，旧引擎不应接受新的范围配方。原片、外部 XMP / ARP 保持不变。


## 亮度照片取样与亮度图（0.20）

`update.luminance` 启用只读亮度输出；`sampleLuminance` 接受当前 revision 和原图归一化 start / 可选 end，返回浮点 minimum / maximum（L* 0–100）、像素数和范围。单击使用 5×5，边缘及裁切处截断；拖框取区域最小 / 最大值。处理旋转后坐标，再与当前裁切求交；越界、过时版本或未启用时明确拒绝。

## 批量导出（0.22）

## 颜色范围（0.23）

引擎 16 新增 `color` 蒙版组件、`colorSamples`（最多五个浮点 L/C/H 与原图归一化取样位置 / 可选矩形终点）和 `colorRefine`。每个样本复用 ART `DeltaEMask`，按最大覆盖率合并；组的添加 / 减去 / 相交、反选和后续局部细节仍使用原有路径。精细度 0–100 映射为 ART range 0.25–19.75，decay=50，L/C/H 权重为 50/75/100。颜色范围使用无额外空间平滑的连续色差权重，防止 guided filter 导致放宽范围时边缘覆盖反而下降，并使亮度 / 色度覆盖一致。

`update.colorSampling` 只控制取样资源。`sampleColor` 复用全质量详细区域、旋转 / 裁切坐标校验及 revision 检查；在 colorcorrection 前缓存完整浮点图像，点取样 5×5，框选按 ART 原有 Lab 通道中值规则得到代表色。新矩形 helper 复用原生色彩转换和中值定义，原有 ART 点选函数未改。区域不是离散色簇集合；复杂多色区域与 ACR 等效尚未证实。新增采样钩子不进入输出路径。

## 导出缩放与输出锐化（0.25）

## 外部蒙版失败保护（0.26）

`validateExternalMasks` 遍历启用的 ColorCorrection、Smoothing、TextureBoost、LocalContrast 及嵌套蒙版分量，使用与渲染共享的 ART 解码器 / 缓存验证文件内容。校验针对合成后的实际参数，已被 CaptRAW 调整替代的旧区域不再作为活动资产；停用工具、停用区域和停用外部分量不要求文件存在。更新在候选参数通过检查后才替换当前状态；compose / validate、详细区域、原生 save、导出和桌面保存也执行检查。对比基线不需要当前编辑的蒙版。

外部图像缓存改为文件路径与内容 SHA-256，避免仅凭大小 / 时间戳复用损坏文件。新增 `ProgressListener::externalMaskError`，与宽高比等非致命警告区分；输出处理器通过独立的蒙版错误监听器传播失败，不改导出进度算法。四个蒙版模块在适屏、详细区域及输出路径都传递读取错误。原生核心用原子失败标记禁止发布预览或写入导出文件；标记在下一次有效更新时复位，并强制完整重算，避免复用失败处理的缓存。外部 profile 变化也触发完整更新。桌面任务仍只在成功时发布临时导出文件。

这不是对象蒙版产品接口：配方仍保存既有 ART 引用，尚未提供可移植、不可变的栅格资产包；外部文件正常替换也不是版本化素材编辑。没有新增模型、ONNX Runtime 或 Python 运行依赖，没有改变有效蒙版的像素算法或配方版本；处理版本仍为 17 / 基线 4。安装版故障与恢复交互由隐藏 E2E 验证，不能替代对象选择的坐标、质量和性能验收。

## 配方的蒙版资产（0.27）

`RecipeV1.maskAssets` 为可选 `{schemaVersion:1, files:[{id,path,bytes}]}`；`id` 是文件内容 SHA-256，`path` 为配方旁资产文件夹中的相对路径。完整 ART 配置使用 `captraw-mask:<id>` 逻辑引用，由 ART 自身 KeyFile 序列化与解析；宿主不通过正则改写用户配置。四类工具（ColorCorrection、TextureBoost、Smoothing、LocalContrast）的递归组件，包括停用但仍有路径的资产，都参与保存。没有外部资产时仍只保存原来的 JSON。

保存先解码核验源资产，再以内容命名、独占发布到 `<配方文件名>.assets/`。按复制后的文件再次核验后，原子替换 JSON。相同内容去重，已有同名资产的内容不符则拒绝覆盖；失败不替换旧配方。保留旧资产与其他文件，不自动清理孤立文件，以免破坏用户复制的其他配方。当前每个资产最多 256 MiB。

打开时严格核查清单版本、大小、SHA-256、引用集合、路径及符号链接，再将同一份已校验字节复制到本次应用的私有缓存，重绑定 ART 路径后才载入照片。即使有缓存，也必须验证配方旁的文件。这样移动原文件夹或清理推理临时结果，不会破坏已经打开的文档；另存会从文档的资产副本生成新的配套文件夹。缺失、损坏或不匹配均报错，不使用上次缓存掩盖错误。

`before-quit` 在进程退出前同步清理本次缓存。原来的未等待异步删除在安装版回归中留下了目录；0.27 对退出后的目录消失增加验证。不自动删除其他应用实例或历史版本的缓存目录。

新的保存标记引擎 18，旧版本将明确拒绝，避免忽略清单后丢失引用。继续读取引擎 2–17 和初版配方；已有配方仅在用户保存到目标路径时更改。源 RAW 仍按现有路径 / 大小 / SHA-256 关联，没有复制原片或新增丢失原片重定位界面。模型、对象提示、栅格坐标与对象选择 UI 不由此协议代替。

## 栅格蒙版组件（0.28）

`MaskGeometry.type="raster"`，`raster` 保存 `path`、文件内容 `sha256`、解码 `width/height`。像素覆盖整个未施加用户旋转 / 裁切的可用图像；坐标不使用 EXIF 原始传感器边界。源图身份仍由 Recipe 的路径、大小、SHA-256 关联。此批没有创建入口或模型部署。

适配器将元数据保存为 ART ExternalMask 的 `CaptRAWRaster`、`CaptRAWRasterRotation/Width/Height/SHA256` 扩展，保留原有组运算。反向映射 0/90/180/270° 后按像素中心做双线性取样，图外边界复制。未带扩展的旧外部蒙版保持原有采样与羽化。

新栅格的羽化半径为当前处理分辨率短边的 `feather/100 × 0.01`，取最近整数；引导滤波固定 subsampling=1，避免区域尺寸跨 600 像素门槛改变采样网格。详细区域保留 2r 加 32 像素边界，不因此申请全图细节缓存。修复前同一受控选区的 fit/detail 覆盖率最大差 50/255；修复后四种旋转均一致，2564×1916 均匀图的缩小 / 区域结果与独立双重盒式均值参考一致。没有把这一结果扩展为任意照片或任意缩放逐像素恒等。

每次使用前核验内容身份，包括命中缓存时；解码尺寸不符、资产损坏 / 缺失时拒绝更新或输出。资产上限 64 MP，继续受宿主 256 MiB 文件限制。保存将原生配置和控件投影共同重绑定为 `captraw-mask:<sha>`，读取时恢复到同一私有资产；核心响应缺少完整投影时拒绝发布 JSON。已停用组件也参与资产收集。

读取已有栅格组件时画布使用平移工具，不出现线性 / 径向控制柄；可使用现有组面板管理和画笔修正。导出使用原生高精度处理，不读取覆盖层的 8 位 PNG。


## 本地对象点选（0.29）

显影核心保持引擎 19 / 基线 4。桌面接口新增 `beginObject(sessionId, adjustments, artProfile)`、`predictObject(id, prompts)`、`commitObject(id, revision, candidateIndex)` 和 `cancelObject(id?)`；进度通过 `object-progress` 事件发送。前端不传模型文件路径、快照文件路径或候选文件路径。

三候选通过私有协议显示，提示修正串行执行且只发布最新结果；在新结果到来前清除旧覆盖，禁止提交旧 revision。提交先核对候选内容散列，再以不覆盖方式复制到 `document-assets`，之后取消临时任务。前端创建中性 raster 组件及一个历史步骤。新对象、取消、编辑参数变化、切换照片和关闭文件使旧选择失效；已提交资产留在文档缓存，供撤销、导出、保存及后续对象选取使用。

对象候选覆盖与提示点沿用画布的旋转 / 裁切 / 缩放变换。选择期间隐藏旧蒙版覆盖与操作柄，离开对象工具取消临时选择；确认后回到常规蒙版面板。模型概率评分不作为边界准确率展示。当前使用 SAM2.1 Small 的三张二值候选，不能表达半透明 alpha。当前工作区另在同一独立 worker 中加载 MediaPipe Selfie Multiclass 六类模型；`parts` 对 256×256 NHWC 输入执行本地推理，按 logits argmax 输出五张原预览尺寸灰度蒙版，沿用相同粗旋转约定。类 0 为背景，不创建蒙版；类 1–5 分别为头发、身体皮肤、面部皮肤、衣物和附件。模型会合并画面内所有人物同类区域，不提供实例选择。

`semantic-masks` 在同一 worker 中加载可再分发的 Apache-2.0 U²-Net FP32 ONNX 权重。输入固定为 320×320 RGB、0–1 NCHW，主输出为 `[1,1,320,320]` 主体概率；宿主按预览尺寸采样并生成 `subject` 与 `255-subject` 的 `background` 灰度 PNG，沿用点选结果的粗旋转、内容寻址复制、revision 校验和文档资产生命周期。该接口输出显著物体，不提供天空类别、人物实例、透明 alpha 或 ACR 算法等效；模型清单、许可、失败边界和证据见 [分割记录](SEGMENTATION.md#当前工作区自动主体与背景)。

`sky` 不增加模型依赖。它在已验证的 RGB 预览顶部采样局部平均亮度、蓝偏、色差与方差，选择 3–4 个连续且平滑的正提示点，然后复用同一 SAM2.1 编码器与候选解码器；选中候选复制为单一 `sky-*.png` 资产。主体概率与 SAM 特征分别按输入 SHA-256 缓存，天空和主体请求的粗旋转只重排同一推理结果，避免相同输入因重复推理的浮点线程差异发生边界漂移。无可信顶部候选或选区低于全图 0.1% 时返回可操作错误。该接口不代表 ACR Sky 的场景分类、树叶间天空恢复或边缘 matte。

## 对象框选与准备代次（0.30）

`crs:Exposure2012` 为 EV，`Temperature` 为色温，四条 `ToneCurvePV2012*` 使用有序点序列（0–255 归一化到核心坐标）。完整黑白组使用 `ConvertToGrayscale` 与八个 `GrayMixer*`，ART 原生基础参数继续保存在私有扩展；缺任一标准字段时整组不应用并显示提示。未出现的字段不参与预设覆盖。曲线插值和显影使用现有 ART 管线，没有证明与 Adobe 像素等效。ART 白平衡精确系数保存在扩展中；外部修改标准色温后，系数失效并转入自定义白平衡。Adobe Tint 与 ART green 的对数单位不同，目前不强行映射。

`https://captraw.org/ns/develop/1.0/` 存放 ART 参数语义、原生处理配置、源文件指纹、基线 4、蒙版和资产清单；结构使用 RDF struct / Seq 与类型限定符，不使用 JSON 字符串。当前可保存全套 CaptRAW 编辑，但尚未将 ART 局部蒙版转换为 Adobe 蒙版。未知 Adobe / 其他命名空间保留在原始 XMP 元数据图中，未接入的 Adobe 字段在工作台与预设列表提示。

保存先发布不可变内容寻址资产，再通过 SDK 序列化、重解析核对，最后原子替换旁车。失败保持原有文件。直接打开 XMP 优先使用源关联和 SHA-256；外部 XMP 根据同目录唯一同名照片关联。默认自动发现同名 `.xmp`；不修改 RAW、ARP 或旧 JSON。当前桌面输入限定 UTF-8 XMP；宽字符输入与完整 Adobe 配置文件、蒙版、修复、自动 / 自适应设置的映射仍待实现。

## XMP 白平衡坐标（0.33）

全局 `temperature` / `tint` 改为 Robertson 色温与 Adobe -3000 缩放的 uv 偏移，范围 2000–50000 K / -150–150，按 CRS 整数类型直接存入 `crs:Temperature` / `crs:Tint`；原照及取样的精确系数不因显示取整而改变。处理版本升为 CaptRAW-20；基线仍为 4。旧 CaptRAW 显影版本明确拒绝，不将旧 ART green 对数值误解释为 Tint，也不恢复 JSON 兼容层。原文件不删除。

`native/white-balance.cc` 复用固定 ART 的 Robertson 表和逆投影，保留 325 mired 的历史 0.24702 项；不是套用 ART 的 daylight / blackbody SPD 数值。存在 DCP 时，通过同一配置文件、光源选择和双光源逆色温插值得到 XYZ→相机矩阵，再把白点转成相机通道系数。没有 DCP 时，使用 ART 的线性 sRGB / 相机矩阵接口。`patchWhiteBalanceAccess` 只公开既有 DCP 转换接口，不改其显影算法。

预览和 `compose` 均在进入 ART 前解析为 `CustomMult`，全分辨率导出直接消费已解析的 ARP。无活动会话的 `compose` 为手动白平衡读取原片以取得相机矩阵；这一读取有额外成本。原照、自动、取样及机身预设仍保存精确系数；显示坐标从当前 DCP / 矩阵反算，超出控件范围时提示近似。切换输入配置或 DCP 光源时，固定系数保持不变，仅重新投影显示坐标；手动白平衡保留坐标并按新矩阵解析。嵌入 ICC 优先于同文件 DCP，转换分支与实际渲染一致。

`ct:ARTWhiteBalanceCoordinates` 记录精确系数对应的两项标准数值。外部修改任一数值会清除旧系数，避免保存的原照系数遮住 XMP 修改。仅含 Temperature 或 Tint 的预设只覆盖该项。保存数值白平衡使用 `crs:WhiteBalance=Custom`；外部其他模式若已有数值，则使用其数值快照并明确提示未重算模式。缺少数值的其他模式保留并报告未接入。

独立参考为 Colour Science 0.4.6，显式调整其已修正的 325 mired 表项后比较 50 组正反投影。自产双光源 DNG 验证相机系数、真实中性灰输出和独立进程 TIFF16。来源：[Adobe CRS 命名空间](https://developer.adobe.com/xmp/docs/xmp-namespaces/crs/)、[Colour Robertson 实现](https://github.com/colour-science/colour/blob/v0.4.6/colour/temperature/robertson1968.py)。

这完成全局白平衡坐标接入，不代表 Adobe 画质等效：尚未导入 Adobe 相机配置或补齐 ART 不支持的 CameraCalibration / AnalogBalance 组合，完整 ACR 色彩管线仍不同。极端色温 / Tint 在某些相机矩阵上产生无效系数时明确报错，不静默裁剪。局部白平衡继续使用已有 ART 相对模型。


## 输入配置文件导入与随附资产（0.34）

桌面“配置文件 → 导入 DCP / ICC”接受独立 DCP 或 RGB 输入、显示、颜色空间类 ICC / ICM。原生 `inspectInputProfile` 使用 ART 的 DCP 解析器及 Little CMS 读取名称、机型限制、嵌入规则和真实处理能力；ICC 须能建立 RGB→XYZ 转换。文件最多 64 MiB。DCP 只用于 RAW，并按声明的机型限制检查；DNG 使用 `UniqueCameraModel`，其余照片使用 ART 提供的相机名称。未声明机型的 DCP 和 ICC 显示适用性提示，不推断不存在的机型约束。

导入先校验复制后的准确字节，再按 SHA-256 存入用户数据目录 `input-profiles`，重复导入复用同一内容。原文件可移走；读取已有绝对路径引用时也先固定到私有内容快照。原生预检查和导出核对内容寻址文件名与实际哈希，避免路径缓存掩盖文件变化。本地库不属于应用安装包，用户导入的配置不进入发行资源。配置名称不作为唯一身份。同名项通过内容标识区分，不自动匹配 Adobe 名称或 digest。

保存 XMP 时，独立配置与蒙版一起放入 `<文件名>.xmp.assets`。`ct:InputProfileAsset` 记录 SHA-256、相对路径及字节数；ART 参数和控件状态使用 `captraw-profile:<sha256>` 引用。读取时先核对旁车资产，即使私有缓存已有文件也不能绕过校验；再恢复为当前进程私有路径。缺失、篡改、越界路径、链接和不一致引用均拒绝。资产先发布，XMP 最后原子替换；不会删除已有资产或替换原片。移动或重命名 XMP 时须保留配套资产文件夹。

`ProfileEmbedPolicy=2` 的 DCP 可用于当前编辑，但拒绝随配方复制；界面说明保存前需改选配置。其他取值仍须遵守配置自身许可，不能把字段值当作第三方资产再分发授权。切换配置沿用当前精确白平衡系数并更新 Temperature / Tint 投影，形成一个可撤销操作。导入回调使用当前控件状态，面板卸载或切换照片后丢弃迟到结果；处理版本仍为 20，基线 4，没有改变已支持配方的显影算法。

Adobe `crs:CameraProfile` 是设置名称，`CameraProfileDigest` 尚未完成与真实 Adobe 输出的成对验证。当前不会把文件 MD5 / SHA-256、ICC ID 或同名 DCP 冒充 Adobe digest；这些字段及增强 Look 原样保留并列为未生效。DCP / ICC 导入、XMP 结构保留和 ACR 像素等效是独立验收项。

依据：[DNG 1.7.1 ProfileName / UniqueCameraModel / ProfileEmbedPolicy](https://helpx.adobe.com/content/dam/help/en/photoshop/pdf/DNG_Spec_1_7_1_0.pdf)、[Adobe Camera Raw XMP](https://developer.adobe.com/xmp/docs/xmp-namespaces/crs/)。

## 点曲线交互与 XMP 名称（0.35）

新绘制和编辑的点采用 0–255 整数坐标，除以 255 后交给现有 ART 自然三次样条；没有更换插值或像素处理算法，处理版本仍为 20、初始基线 4。已有 XMP 的小数点坐标保留，聚焦、选择和保存不触发取整。输入框允许临时留空，Enter / 失焦提交，Esc 恢复编辑前坐标；拖动和方向键手势分别形成一步历史。端点也可修改输入值，邻点约束始终保持 X 严格递增。

保存包含点曲线的文档 / 预设时同步 `crs:ToneCurveName2012`：完整四条曲线均为两个恒等端点时写 `Linear`，其他写 `Custom`。部分曲线预设不补齐未给出的通道；没有曲线的预设不新增名称。读取仅名称而无坐标的输入不生成曲线；名称冲突或未确认的名称关系给出提示，实际采用记录的点。非法空坐标、非十进制或非有限数字明确拒绝。

本机 Adobe 随附 Settings 中 1,370 条 PV2012 序列、4,576 对坐标均为整数，作为写法参考。它们跨多个 Adobe 版本，不是 ACR 18.7 往返验收。[Adobe CRS 文档](https://developer.adobe.com/xmp/docs/xmp-namespaces/crs/) 的 Integer 定义仅针对旧 `ToneCurve`，不能据此声称 PV2012 拒绝小数。Adobe 对冲突名称的优先级、小数处理、插值与最终像素等效仍未验证。

## 镜头校正后的白平衡取样（0.36）

ART 的 `getSpotWB` 原先调用 `transCoord` 时没有传入镜头映射，开启校正后会采到显示位置之外的原片像素。渲染与吸管现在共用 `getLensCorrection`，沿用原有 EXIF / Lensfun / LCP 选择、焦距和旋转参数。色差校正在畸变处理之后渲染，因此吸管先逐通道逆映射色差，再交给原有 `transCoord` 反算畸变、旋转和自动填充。

此修正改变新取样结果，不改变已有系数、配方格式或渲染算法；处理版本 20、基线 4 不变。`tests/white-balance-optics.mjs` 对 RGB 和人工 Bayer DNG 的 48 组实际预览目标取样，覆盖自动 / 手动镜头、四方向旋转、裁切、畸变和色差；同配方预览与 0.35 逐字节一致。测试 DNG 使用人工 CFA 数据和已知镜头 EXIF，不冒充实拍 Nikon RAW。`tests/white-balance-optics-e2e.mjs` 经界面点击验证适屏 / 1:1、裁切、撤销和 XMP 恢复。透视和任意角度拉直尚未接入；不能由此推断 Adobe CropAngle 或 Orientation 的完整互操作。

## 批量 XMP 保存（0.37）

`BatchDocumentSaver` 接收选定照片的不可变快照；每张通过独立核心 `compose` 将当前调整覆盖到已有完整 ART 配置，随后记录原片 SHA-256、使用官方 XMP SDK 序列化并保存资产。它不切换正在显示的会话，不需要重新生成全分辨率图像。未知 XMP 属性从各自的原始包保留。

保存到用户选择的文件夹，以原片名生成 `.xmp`。已有文件或资产文件夹会触发编号；最终发布使用核心的原子“不替换”操作，检查后出现同名文件也不覆盖。`saveRecipeWithMasks` 默认覆盖行为保持不变，只有批量新文件显式使用不替换模式。蒙版和输入配置的内容寻址、许可策略和完整性检查沿用现有链路。

每张成功或失败单独返回，只有成功快照更新对应的已保存状态，不清除撤销历史。取消及保存中退出均等待当前文件完成，随后跳过剩余照片；已发布文件保留，未保存照片继续保持脏标记。此操作是批量另存，不宣称整批文件系统事务，也不会自动更新已有原片旁车。重开当前照片的 XMP 保留胶片位置，避免 Shift 连选范围改变。

### 后续任意角度接入的已核实边界（未实现）

固定 ART 中，修复点在 `transform` 前消费，颜色 / 亮度范围和局部覆盖在其后消费；不能将 fine angle 简单加入 `recipe.cc` 的共用 coarse `rotate`。`transCoord` 是目标到源的逆映射且带边界裁剪；`getTransformAutoFill` 必须与照片使用同一参数。径向需要保留轴长并使用 `AreaMask::Rectangle::angle`，画笔需同时处理中心、半径及羽化尺度，栅格需扩展逐像素逆映射；关联覆盖不能再次变换。对象分割输入、详细预览的邻域和所有取样坐标也必须一致。

这些结论来自 `improccoordinator.cc`、`dcrop.cc`、`simpleprocess.cc`、`improcfun.cc` 和 `masks.cc` 的阶段核对，不是运行验收。含非线性镜头畸变时，仅旋转中心和端点不足以表达完整覆盖形变；Adobe 非零 CropAngle / Orientation 的独立参考仍缺失。没有加入会破坏既有选区的角度控件。


## 前后对比预览（0.38 / 0.41）

四种布局共享图像坐标、裁切、缩放和平移。主显影进程继续输出当前编辑及其详细区域；独立对比进程读取同一原片。0.41 默认参考改为打开照片时的完整调整及 ART 配置，包括导入 XMP；可将当前编辑存为前状态、交换前后设置、还原打开时参考。前状态渲染继承当前已接入的裁切、90° 旋转和镜头校正（含镜头暗角）；交换也保留这些几何设置及裁切比例。未暴露的 ART 几何参数不在此次对齐保证内。

对比使用独立 revision、事件和私有预览 URL，参数更新合并于 React 状态。开启对比、替换参考或改变上述几何状态时重新渲染前状态；普通调色不重算参考。1:1 两侧请求相同原图区域，并按物理屏幕像素绘制。P 和按住对比也使用这个独立进程，不替换主预览、缩略图或主核心参数，保留当前缩放 / 平移；单图查看前状态时，RGB 直方图同步显示该参考的实际统计。退出对比、成功切换文件及退出应用时终止参考进程并清理缓存；失败打开文件保留当前对比。错误按会话 / revision 过滤。

会话文档分别持有打开状态和可选自定义前状态；胶片切换保留，关闭文档后释放，不写入 XMP。历史记录保存完整调整及 ART 配置，以保留未暴露参数；全配置替换携带会话内身份编号，保存和撤销同时检查编号与调整值。交换是一条同时恢复当前编辑和前状态的历史记录；保存 / 还原前状态不标记未保存，也不额外占用撤销历史。普通编辑撤销不撤回独立设置的对比参考。

底栏选择布局，Q / Shift+Q 循环；P 切换预览、Option/Alt+P 保存前状态、Shift+P 打开预设，参照 [Adobe 官方快捷键](https://helpx.adobe.com/camera-raw/desktop/get-started/overview-and-setup/default-keyboard-shortcuts.html)。移除旧版将反斜杠当作 P 的映射；Adobe 的反斜杠“交换当前与默认全部设置”、独立参考图、持久快照及完整快捷键集合尚未完成，未宣称 ACR 全集一致。原生 CLI 的 `before` 仍提供 RAW 初始帧，桌面不再通过该命令实现对比。

## 完整可见区域的 1:1 预览（0.39）

前端将画布边界反变换到原图，与原图范围取交集，再向外取整得到整数区域；分别计算右 / 下边界，避免小数平移时漏掉边缘像素。主图和对比图请求同一矩形。核心只按原图剩余尺寸裁定范围，移除前后端 2048×2048 截断；不是将适屏图插值填补边缘。

同一 revision 的适屏图刷新保留已解码的详细图。详细图仅在 URL 与对应帧元数据相符时绘制，避免旧位图按新位置绘制；对比侧的适屏位图尚在加载时，也可独立绘制有效详细图。退出 1:1 后不绘制详细层。

0.39 额外发现局部明暗的裁切上下文差异：ART `simpleprocess.cc::stage_finish` 在 Stage 1/2/3 前裁切，详细预览的 `fullDetailContext()` 则对全图计算局部滤波。D850 线性蒙版 / 局部高光与裁切组合，RGB8 量化参考最大差 5；0.38 与 0.39 的重叠区域完全相同，表明不是扩大区域引入。原失败证据 `artifacts/wide-detail/cropped-tone-unresolved.json` 保留；0.40 修复见下节。宽区域测试中的局部明暗使用未裁切全图输出作参考，不能单凭该测试宣称裁切组合通过。

## 裁切内局部明暗预览（0.40）

启用局部明暗且裁切有效时，适屏 / 详细预览的 Stage 1/2/3 使用 `processPreview`：每阶段先保留裁切内输入，计算框外所需的原预览，再以导出相同的裁切取整、原图尺寸和坐标处理裁切内输入，合回同一全图坐标。下一阶段读取已经修正的裁切内结果。只修正明暗增益不足以得到一致结果，因为蒙版生成也有空间滤波；因此整个三阶段处理链共用裁切上下文。Stage 0 和导出路径不变，处理版本 20 / 基线 4 不变。

两次计算的链接蒙版缓存独立保存。覆盖率、亮度及颜色取样通过同一裁切范围合并后再通知宿主；只保存宿主需要的蒙版，避免为每个隐藏蒙版复制全尺寸覆盖率。既有详细图缓存和平移继续使用完整图像坐标，框外像素可用于重新构图。关闭核心时这些缓存随处理器销毁。

当前触发条件是启用且非中性的局部明暗；没有将所有空间滤镜、所有缩放率、全部原生 ARP 参数组合宣布为一致。完整区域之外的独立取样裁块仍沿用现有路径。增加了一次裁切内处理和临时浮点缓冲，尚未完成大图 / 多蒙版 P95 与峰值内存验收。测试 `cropped-tone.mjs` 对照 0.39 输出与旧预览，`cropped-tone-e2e.mjs` 验证实际 GUI 的裁切、蒙版、撤销、XMP 重开、详细预览和 TIFF16。

## 几何坐标与白平衡取样（0.42）

`native/geometry-map.{h,cc}` 复用 ART 的镜头选择、`transCoord`、填边和 `PerspectiveCorrection`。坐标为已完成 coarse rotation 的完整图像像素中心，不含裁切偏移，也不是 Web 的归一化坐标。`toSource` 从最终几何输出回溯透视、独立镜头色差，再回溯组合畸变 / 填边 / 任意角 / 手动色差，通道 0/1/2 分别取 RGB。标量定位默认用绿通道；这不代表能同时精确对齐三通道。

`transCoord` 新增默认开启的裁边参数；现有处理调用保持原行为，映射使用无裁边结果，避免将图外坐标压到图像边缘。`toDisplay` 对同一采样函数作带步长回退的数值求逆，成功时原始采样残差小于 0.002 像素；失败返回 false，不修改输出参数。使用一像素中央差分，避免 Lensfun 浮点坐标在大图上使微小差分消失。它不是所有异常镜头配置均可逆的保证，也不是直接逐像素生成整幅蒙版的性能方案。

ART 的填边计算会读取已停用但保留数值的手动色差；实际图像采样忽略这些数值。映射先计算实际填边，再对采样清零停用系数，保持固定配方输出。白平衡吸管使用共享映射并沿用原有图像边界限制，修正继承 ART 透视及上述色差状态时的取样错位；没有改写已有白平衡系数。持久参数、处理版本 20、基线 4 和输出管线不变。

验证包括 80 组 ART 浮点坐标渐变图、8256×5504 坐标往返、无填边时图外点可逆，以及 RGB / 受控 Bayer 的光学校正回归。真实图像采样与数学坐标有插值差异，两者分别报告；不能把坐标往返精度当作图像插值无误差。`geometry-mapping.mjs` 生成带 EXIF 的受控图和 XMP，比较 0.41 旧核心的取样及 TIFF16；`white-balance-optics-e2e.mjs` 必须先运行该脚本。

任意角交互仍未接入。ART 的 drawn / area / external mask 位于几何变换后，修改角度时不会自动跟随被摄物；修复点则位于变换前。下一步蒙版映射必须区分这些阶段：若 canonical 坐标已含零角度镜头校正，则当前输出到 canonical 为 `inverse(F0) ∘ Fθ`，不能重复应用镜头校正。原始坐标和栅格资产保持不变，覆盖率、操作手柄、修复点、范围取样及 `crs:CropAngle` 要分别接入并验证后，才能宣布拉直可用。

### 蒙版覆盖率映射与画笔精度（0.43）

`GeometryMap` 可额外接收完整处理尺寸，按 ART 的 `fW/oW` 比例处理预览透视，保留缩略尺寸取整行为。`GeometryField` 在同一处理尺寸内计算 `inverse(Freference) ∘ Fcurrent`，以自适应四叉树缓存标量坐标；单元角点、中心及边中点校验误差，跨度最多 128 像素，无法收敛的细分单元采用逐点计算。默认探测容差 0.02 像素不是所有坐标的严格误差上界。两个 GeometryMap 必须活到全部并行读取结束。仅引用同一映射实例时明确标记恒等并旁路重采样。

`patch-mask-geometry.mjs` 给 `generateMasks` 增加可选坐标场，默认 nullptr 保留原路径。area 按形状生成参考画布覆盖率，在当前图像引导羽化、模糊和合成前重采样；drawn 在有符号笔画编码后、平滑和羽化前重采样；external 直接映射资产采样坐标，避免先重采样资产再变换。递归组只变换叶子，关联缓存存储当前区域的最终覆盖率，不重复变换。颜色 / 亮度参数选区继续使用当前处理图像。

合法图外覆盖率为 0，有符号画笔编码背景为 0.5，减去形状的背景为 1；外部蒙版反选后取补集。逆解失败与图外坐标区分，先结束并行采样再抛出错误，调用方必须丢弃未完成结果，不能把失败当作零覆盖或满覆盖。参考栅格只读，资产解码缓存不保存几何变换结果。补丁对固定源码及重复应用已验证；检测到早期未版本化的生成代码时明确拒绝，重新从固定源码压缩包生成 `build/upstream/ART-*` 后再构建。

正式处理调度现已接入适屏、详细区域、缩略图及完整输出；`MaskGeometryCache` 由每个 `ImProcFunctions` 持有，保留两个处理尺寸的映射及其源对象。缓存键包含源尺寸、元数据、旋转、透视、畸变、填边、镜头与色差；曝光、裁切和蒙版本身不重建坐标场。调用在原处理锁内完成，映射及源对象活到并行处理结束。

参考画布通过 `[Rotation] CaptRAWMaskCoordinates` / `CaptRAWMaskReferenceDegree` 持久化。缺省关闭，读取没有这些字段的 ART 配置时明确清除先前状态；启用时当前及参考有效角均须为有限的 ±45°。两者相等时不重采样；当前角为零而参考角非零时仍执行映射。逆解失败使用专门错误回调停止处理，核心不发布失败帧，也不写出导出文件。

局部预览的源范围修正：存在镜头畸变 / 色差或有效透视时，读取完整中间变换画布，输出仍仅编码请求的区域。原来的源边界及 15% 余量不能保证二次采样所需的中间像素，曾在全图 1:1 预览产生导出中不存在的黑边。此修正可能增加大 RAW 的详细区域处理时间和内存，尚未完成 45 MP 性能验收。仅因当前局部区域没有蒙版覆盖时不报整幅蒙版为空；完整画布为空仍保留原有提示。

画笔存储修正：ART 标准 `DrawnMaskStrokes` 使用半精度打包，无法保留预览中的完整坐标和半径。保存新增 `CaptRAWDrawnMaskStrokes` double 列表并优先读取，包含添加 / 擦除顺序；校验非有限值、段长及不完整数据。缺少扩展时读取原 ART 列表，不改动原文件。仍同时写入标准字段，原版 ART 会读取其中的量化值，不能宣称与 CaptRAW 的画笔像素完全一致。处理版本提升至 21，使旧核心拒绝新 XMP，防止静默忽略这些语义。

**接入边界：** 以上已随 0.43 核心分发并完成安装版受控图像验证；未增加用户可见的拉直控件。前端手柄 / 新笔画坐标、修复点、范围取样和 `crs:CropAngle` 尚待连接与验收。0.43 的处理配置只有一个蒙版参考角；工作区的独立叶子参考角见下节。既有 `LinkedMaskManager::init` 只注册顶层关联依赖，components 内独有的关联引用仍未纳入通过声明。

## 独立蒙版参考角与坐标查询（0.44）

0.44 写入处理版本 22，读取 20 / 21 / 22；旧 0.43 仍为 21，不能读取新写出的 22 文档。`MaskGeometry.referenceAngle` 是空间叶子的细旋转参考画布角度，有限值 ±45°，不是 Adobe CropAngle。ART 以带组件前后缀的 `CaptRAWReferenceAngle` 保存；存在标志参与 equality，缺键清除复用对象状态。没有该字段时保留原配置全局行为；未启用全局映射时保持当前画布 identity。颜色 / 亮度参数选区仍取当前图像，不使用该空间映射。

生产生成器通过 resolver 按叶子选取映射；映射指针只在当前叶子的空间处理期间有效，不跨递归或下一次缓存查询。两条缓存记录同时包含处理尺寸和参考角，超过两种组合可能重建，不宣称混合蒙版已达到性能目标。组、已生成的关联覆盖图不重复变换。

`validate.masks` 返回深复制并绑定后的蒙版：显式角保留；缺省角采用来源的全局参考角或当前有效细旋转角。打开 XMP 使用该投影；捕获新预设和同步时先绑定来源，再使用目标配置处理，不搬运来源其他 ART 设置。旧预设没有来源角时按目标配置绑定，保持原有行为。独立蒙版转为组件时保留该字段。原用户 XMP 不自动写回，JSON 文件兼容不恢复。

`coordinates` 的 `source` 表示细几何变换前画布，`display` 为当前画布，`reference` 为指定参考角画布；各自保留当前其他光学 / 透视设置。默认参考角遵从当前配置的全局参考角，否则使用当前有效角。点使用全画布像素中心单位，输入不是裁切后屏幕坐标。Web 宿主通过受限 preload 转发，查询不改变参数或预览。16 组真实渲染坐标对照见 `artifacts/coordinates/report.json`，不能据此认定新笔画、操作手柄或修复点已经接入。

原生和隐藏 GUI 证据见 [验收记录](ACCEPTANCE.md)。拉直入口、对象候选变换、修复点 / 范围取样联动及 Adobe CropAngle 仍未交付。

### 空间蒙版画布交互

画笔 / 擦除先在当前显示画布按笔刷间距插值，再按原生 `coordinates` 逐批映射到组件参考画布；每批最多 4096 点，一次只有一个笔画映射请求在途。归一化使用全画布 W / H，并逆转粗旋转，与 ART drawn / area 参数一致，不引入半像素偏移。笔刷半径仍属于参考画布；非线性变换后的覆盖不保证是显示画布上的正圆。无法逆解或映射超出当前归一化参数可表达的参考范围时，整次未提交草稿取消并显示错误，不把失败坐标压到边缘。

拖动期间只显示本地草稿，不更新文档或原生处理 revision。松手位置也采样，所有待映射点排空后只提交一步历史。手势绑定照片、revision、编辑序号、参数对象和实际预览选项；预览尚未就绪时明确拒绝开始，已接受手势会取消完全重复的待发送刷新。切换工具 / 组件 / 照片或其他编辑会使迟到结果失效。已有手柄使用相对拖动量保留抓取偏移，仅单击不改变文档、不清空重做记录。

尚未提交的笔画也计入应用退出保护。处理期间保存、关闭文件、导出及同步入口明确提示等待完成后重试，不刷新核心 revision 或保存旧快照；取消原生关闭 / 退出提示后仍可继续等待该笔画。草稿结束、取消或组件卸载时释放保护；正常提交与脏状态更新处于同一批界面更新。验收使用延迟的真实坐标响应检查这些竞态，不能以普通快速响应掩盖数据丢失。

线性和径向轮廓在参考画布上采样，再完整映射到显示画布；径向不以两个变换端点拟合椭圆。起点、终点和参考中心分别映射，命中测试使用同一显示位置。自适应细分检查四分之一、中点及四分之三位置，CSS 弦误差采样阈值 0.125 像素；这是采样准则，不是任意函数的严格误差界。空逆解分段显示，真实映射失败提示错误并允许单击画布重试。原生最终覆盖 PNG 已在当前画布，前端不重复变换。

切换照片时，旧核心仍在处理的 1:1 或参数更新请求可能随核心替换而拒绝。界面只显示当前照片、当前 revision 的请求错误，旧请求不能清除新照片的忙状态或留下退出警告；当前请求的真实故障仍显示，不能用统一吞掉错误来避免误报。

### 修复点画布交互（0.45）

修复发生在 ART 细旋转、透视和镜头变换之前。屏幕输入先减去图像绘制原点、除以 CSS 缩放，再减去 0.5，转换为显示画布像素中心；`coordinates(display, source)` 得到修复域位置。保存沿用原有归一化坐标：以打开照片时的原始尺寸按粗旋转交换 W / H，除以 W−1 / H−1 并逆转粗旋转。RPC 返回的画布尺寸单独校验；导入配置改变 RAW border 时，不拿变化后的画布尺寸替换旧配方分母。已有坐标不会因显示或保存被重新取整。

轮廓先按 `recipe.cc` 对保存点进行粗旋转与整数像素中心取整，再映射到显示画布；Canvas 投影只在此处加 0.5。源和目标各自的半径、羽化外圈均完整采样映射，不能用变换后的中心加屏幕圆代替。羽化外圈按 ART float / 整数半径规则计算；低分辨率预览另有 skip 取整，不宣称轮廓逐像素贴合所有适屏边缘。

`useRepairGesture` 与蒙版共用画布事务：固定 session / revision / 参数快照，未提交操作纳入保存和退出保护。取样来源不创建历史；目标创建、源点或目标点拖动各提交一次。拖动采用两个屏幕位置映射后的源域差值，保留抓取偏移；松手位置纳入最终请求。Esc、换工具 / 照片 / 修复点、参数变化或画布尺寸变化会取消草稿，迟到响应不写文档；越界和逆解失败明确报错，不把位置静默压到边缘。无移动点击保留原参数和重做记录。

此接入不更换 ART 修复算法、处理版本或 XMP 参数定义；仍为引擎 22 / 基线 4。范围取样、对象候选和 Adobe CropAngle 不在本节完成范围。


### 对象选择的当前几何快照（0.46）

对象快照保留当前粗旋转、细旋转、镜头和透视，只取消裁切。模型在当前方向的完整 sRGB 预览上推理，宿主将原有 canonical 归一化提示旋转到输入画布，再转换为像素中心；框选两角转换后重新排序。原生分割进程通过 `outputRotation` 将二值候选反向整转回 canonical 存储方向，不插值、不重跑模型；返回的 `width/height` 描述输入，`maskWidth/maskHeight` 描述资产。默认零角度的 PNG 字节保持不变。模型不保证旋转等变，不能要求不同方向的独立推理生成相同选区。

显影 `update` 返回实际应用的 `geometry:{rotation,angle}`。`commitObject` 返回 `{raster,referenceAngle}`，新叶子绑定快照的实际细旋转角，不继承旧蒙版全局参考角。处理版本仍为 22、基线 4，已有资产和 XMP 字段语义不变。宿主候选键包含完整 ART 配置，前端准备快照和失效检查包含 `profileId`；仅配置改变而控件值不变也取消旧任务。

此修正验证创建时的候选与提交对齐、细旋转参考及保存恢复。参考角仍沿用当前其他光学和透视设置，没有保存完整历史几何；任意后续光学 / 透视 / 粗旋转组合中的内容锁定仍需单独验证。范围取样、拉直入口及 Adobe CropAngle 未因此完成。


### 对象启动与预览忙状态（0.47）

“选择对象”只因照片载入或前状态对比而禁用，不因普通预览刷新禁用。进入蒙版工具的覆盖刷新有 90 ms 合并窗口；旧行为可能在真实 pointerdown 与 pointerup 之间将按钮禁用，使浏览器不产生 click。入口沿用 `flush()` 获取最新完整配方，随后独立准备模型输入；没有绕过原生排队、参数失效检查或取消代次。

画布仍记录空格按住状态以支持“先点击 1:1，再空格拖动”的操作；焦点位于按钮、链接、summary、ARIA 按钮 / 滑杆 / 标签时，不再 preventDefault，保留控件原生键盘行为。输入框、选择框与可编辑文本不参与画布空格处理。空格释放照常解除临时平移。没有改动图像处理、XMP、模型和配方版本。

### 手动角度调整（0.48）

裁切模式提供 −45° 至 45° 的角度输入、0.01° 滑杆步进和独立重置。`fineRotation` 是 ART 有效细旋转角：存在时控制 `Rotation.Enabled / Degree`，缺失时保留完整 ART 配置。请求值等于有效角时保留原设置，包括已关闭但仍储存非零 Degree 的配置。新照片返回 0；旧 XMP 未携带此字段时，打开阶段先移除新照片的默认值，再由 `validate` 投影实际角度，防止覆盖旧配置。

已有空间蒙版在应用新角度前补齐缺失的叶子参考角；显式参考角不改写。预览缓存随角度失效，当前构图中的前后对比、前后交换、裁切同步和预设均包含该字段。保存使用现有 ART RDF 调整扩展和完整 ART 配置，处理版本仍为 22、基线 4；没有更换重采样算法或把预览图用于导出。

0.48 本入口支持手动数值旋转；画线拉直在下节 0.49 接入，自动水平、约束裁切入口及 Adobe `CropAngle` 映射仍未完成。ART 原有 AutoFill 参数保持原值，不将它声明为已经对齐 ACR 的约束裁切。

### 画线拉直（0.49）

裁切工具内选择“拉直”，沿希望水平或竖直的边缘拖线，松手应用，返回裁切。端点在当前完整显示画布的像素中心坐标中传递，缩放、平移和粗旋转均不改变其定义。拖动期间只画参考线，不反复渲染。短于 4 CSS 像素的操作不调用核心、不创建历史；结束位置计入笔画。

`straighten(sessionId, revision, start, end)` 是只读求解接口，返回 `{angle, axis, previousAngle, residualDegrees}`。按当前线段最接近的方向选择水平或竖直，45° 平局选水平，反向画线结果一致。核心先用当前 `GeometryMap` 将两端还原到变换前，再保留镜头、透视及 AutoFill，仅改变细旋转求取投影端点对齐的角度。扫描 ±45° 并对有效区间细化，最多 192 次候选映射，选距离当前角最近的根；结果量化至 0.01° 后复核残差不超过 0.02°。无解、逆映射失败、越界、旧 session / revision 明确拒绝，不夹角、不改变粗旋转或裁切。求解本身不改配方、不发预览。

前端以现有画布事务绑定当前照片、参数、revision 和视图。仅成功返回且事务仍有效时写入 `fineRotation`，形成一步历史；Esc、换照片 / 工具、参数或视图变化取消草稿和迟到结果。待返回操作受保存 / 关闭 / 退出保护；1:1 与适屏按钮在笔画期间禁用，对比模式禁用拉直入口。蒙版参考角、完整配置与 XMP 持久化沿用 0.48，不新增文档版本。

这是两端参照线的人工拉直，不代表自动地平线检测、镜头曲线变直或透视全集。已有镜头 / 透视参数仍由原配置提供；没有增加这些调节的 UI，也没有新增 Adobe CropAngle 映射。


## 范围取样的操作保护（0.50）

颜色和亮度范围用 `useRangeGesture` 固定鼠标按下时的 session、revision、文档、组件及视图。拖框只维护本地草稿，松手位置纳入最终区域；取样直接消费匹配当前显示的核心 revision，不通过额外 flush 在手势途中更换参数。结果只在同一事务仍有效时应用一次，既有样本 / 范围不重算；不改引擎 22 / 基线 4 或 XMP 参数定义。

从按下到结果返回，未提交操作纳入保存 / 导出 / 关闭与原生退出保护。Esc、换照片 / 工具 / 组件、参数变化、对比或视图变化取消草稿并释放保护；旧任务完成或失败不覆盖新操作的取样状态。等待期间禁用适屏 / 1:1 按钮及滚轮缩放。取消后的原生计算可能继续完成，但不得再改写配方。

原生 `sampleColor` / `sampleLuminance` 接收去除粗旋转的归一化显示位置，内部旋转后在几何变换完成的浮点数据上取样；不能再次用源图逆映射。`range-geometry.mjs` 以安装版 0.49 的 32 组受控 PNG 核查细旋转、镜头畸变 / 色差、透视、粗旋转和 AutoFill，目标从渲染像素定位，包含旧位置负对照。此检查不涵盖 GUI 坐标、裁切、真实 RAW 或所有处理组合；颜色样本标记在后续几何变化中的跟随仍待完成。

`range-transaction-e2e.mjs` 在隐藏安装窗口中检查两类范围的草稿保存 / 关闭、取消、等待真实 RPC 时的保存、对比取消、窗口尺寸变化及一步撤销。`color-range-e2e.mjs` 延迟真实原生结果验证切换工具，不使用虚构取样值；等待实际新预览后才开始下一次操作。


## 颜色样本标记的源图定位（0.51）

新建 / 替换颜色样本增加可选 `sourcePoint`，表示几何变换前、粗旋转前的显影图像像素中心位置，按 W−1 / H−1 归一化。它不是相机传感器的原始 CFA 地址。点取样保存取样点，矩形取样保存选框中心；先取得实际颜色，再在同一 session / revision 下通过原生 `display → source` 映射。两次请求都处于范围取样事务，取消或状态变化不写入颜色或定位点。

显示时按当前粗旋转和完整尺寸还原源图像素中心，再通过原生 `source → display` 映射。标记绘制和 Option 删除命中共用同一结果；图像、参数或组件变化后不使用旧 revision 的标记，异步旧结果被丢弃。映射失败保留颜色样本，显示重试入口，右侧样本列表仍可管理。

`point` / `end` 保留原取样区域；`l` / `c` / `h` 不因几何变化重新采集。`sourcePoint` 仅用于界面定位，经原生边界校验后作为 ARTAdjustments 的 RDF 结构保存，不写入 ART 处理算法或 Adobe 标准蒙版字段；引擎仍为 22 / 基线 4。未记录定位信息的样本维持已有显示位置，界面提示重新取样，既有 XMP 不自动改写；不能从旧记录推断历史镜头 / 透视和角度。

`color-pin-e2e.mjs` 从实际画布红色色块定位，验证正负角度、四方向粗旋转、Lensfun 畸变 / 色差、导入的透视组合、变换后重新取样、适屏 / 物理 1:1、Option 删除和单步撤销、XMP 重开、无定位文档保护、延迟真实定位结果的取消，以及 TIFF16 与独立 0.50 输出一致性。透视由测试 XMP 提供，不能称为已完成用户透视面板。此验证限于受控 PNG 和指定参数，完整 RAW 几何、所有镜头及跨图片预设的定位仍需单独验收。

## 手动透视接口（0.52）

`Adjustments.perspective` 保存 `enabled`、`horizontal` / `vertical`（−200–200）、`angle`（−20–20 度）、`shear`（−50–50），以及原 ART `focalLength`（0–1200，0 保留原自动语义）、`cropFactor`（0.1–10）、`aspect`（0.5–2）。界面开放前四项数值和开关；其余投影值保留用于完整配置恢复和同步，不新增未验证的控件。复位清除整个透视设置，裁切 / 细旋转保持。

字段缺省保留 ART 配置；读取已有 XMP 时通过 `validate` 投影真实设置，避免新照片的默认值覆盖已有透视。预览更新使几何缓存和蒙版覆盖失效，前后对比与交换设置沿用当前透视。独立 `perspective` 同步组默认不选；预设按需包含。

处理算法及版本 22 不变。参数存储为 XMP 中带类型的 ART RDF 扩展和既有 ART 配置；尚无证据证明与 Adobe `crs:Perspective*` 数值 / 画质等效，因此这些 Adobe 字段继续保留并报告未生效。自动校正见下节；引导校正及完整 ACR 变换仍未完成。

## 自动透视接口（0.53）

`autoPerspective` 分析当前配置快照，支持 horizontal / vertical / both，返回完整透视设置，不修改活动文档。桌面服务在独立原生进程完成读取与预览准备，再调用 ART `PerspectiveCorrection::autocompute`；结果仅在文档、处理版本、工具状态仍有效时作为一步编辑应用。保存 / 退出沿用画布事务保护；取消按任务 ID 终止独立进程，进程退出后清理目录。手动编辑、切换照片 / 模式和 Esc 也取消并拒绝迟到结果。

沿用 ART 约 900 像素分析尺度、LSD 线段检测和 ashift 拟合，不新增模型。上游接口新增可选成功标志，失败明确报错而不把原参数误当新结果；越界解不截断。Sobel 边框填充修复为仅从已初始化内部像素读取，避免角点垃圾值与并行竞争；固定配方渲染算法未改。引擎仍为 22，自动结果保存为已有透视字段，不引入新的文件格式。

自动模式检测照片中的结构方向，不等于语义识别地平线。没有足够直线或拟合不可靠时保留编辑，用户可手动调整或画线拉直。RAW 解码 / 取消验证不代表真实照片自动透视质量已达 ACR 水平。

## 引导透视（0.54）

`autoPerspective.lines` 可选：2–4 条全尺寸、粗旋转后当前显示像素中心坐标，端点限定在照片内，`axis` 为 horizontal / vertical。每个参与方向恰好两条；有两类时联合拟合。原生通过当前 GeometryMap 逆映射到源图，再映射至禁用透视但保持细旋转 / 镜头的画布，传给 ART ControlLine。检测重合、退化、越界和过时请求；拟合成功后再次映射源端点检查每条目标方向残差不超过 0.1°，避免优化器到达边界却报告成功。求解本身不改文档。

`Adjustments.perspectiveGuides` 是引导线编辑元数据，保存未粗旋转源图的归一化像素中心位置（W−1 / H−1）与该坐标系中的轴向，最多四条。存在 XMP 的 ART RDF 扩展中，不改变固定 ART 配方渲染；没有此字段的文档保持无引导线。当前旋转 90° / 270° 时交换水平和垂直轴。显示与端点拖动使用同一原生正反映射，缩放和平移只影响显示。它不是 Adobe Upright 引导线格式，也不从上游 ART control_lines 自动推断源图位置。

0.54–0.56 中画线和端点拖动从按下开始处于画布事务，直到显式应用或取消；编辑草稿和等待结果均受保存 / 导出 / 退出保护。应用时参数及引导线作为一步历史保存；失败保留草稿供修改。Esc、工具 / 文档 / 参数切换、失效结果会取消。引导线随独立透视预设 / 同步组复制，使用归一化位置，不对目标照片自动重新识别直线。清除全部引导线后应用只删除编辑线，保留透视数值。

0.54 为显式应用的成对线工作流；0.55 扩展三条混合线，ACR 式每次画线后实时变换、放大镜及全部快捷键仍未完成。Adobe [引导透视说明](https://helpx.adobe.com/sg/camera-raw/desktop/edit-and-enhance-images/crop-rotate-and-geometry/automatic-perspective-correction-camera-raw.html) 描述两条以上引导线后的交互变换，此处列为继续对齐的差异，不宣称完整等效。

## 三条混合引导线（0.55）

接受 2H+1V 或 1H+2V，原有 2H、2V 和 2H+2V 保持。三条线只拟合旋转、水平透视、垂直透视三个参数，shear 固定为零，沿用当前焦距 / 裁切系数 / aspect；不能把四自由度拟合用于只有三条角度约束的输入。仅明确传入且严格计数匹配的三条引导线启用此路径，自动检测的最少线数和四条线的 shear 拟合保持原语义。

求解后仍检查每条已选线实际几何残差 ≤0.1°；不收敛、越界或残差不合格时保留原编辑并报错，不复制虚构线、不夹值。三条线以相同源图坐标和 XMP 元数据保存，撤销恢复整次编辑；未指定的第四条边缘不在验收约束内。数值 / 渲染保持 ART 语义，不宣称 Adobe Upright 算法等效。固定配方渲染和处理版本 22 / 基线 4 不变。


## 引导透视放大镜（0.56）

放大镜只在引导透视模式和图像内出现，复用当前处理 revision 的详细区域接口。200% 指每个显影像素占 2×2 物理屏幕像素；定位保持像素中心约定。等候详情时显示加载状态，不使用适屏缩略图冒充原分辨率。详细区域同时校验 session、revision、完整尺寸、加载 URL、图像尺寸和覆盖范围；在 1:1 状态请求区域包含可见窗口，避免放大镜请求替换主要视图的细节。

Shift+L 在此模式切换放大镜，不创建亮度蒙版；Option 拖动临时显示并以四分之一增量移动当前端点，松开 Option 后继续普通增量，避免端点跳到鼠标绝对位置。状态仅在界面内保存，不修改显影配置或 XMP；处理版本仍为 22 / 基线 4。

操作参考 [Adobe 专家 Julieanne Kost 的 Camera Raw 快捷键说明](https://jkost.com/blog/2022/10/225-shortcuts-tips-and-tricks-for-adobe-camera-raw.html)。该说明针对较早的 Camera Raw，不代替本机 18.7 全部快捷键 / 手感验收。仍缺实时引导变换与完整 Adobe 透视参数语义。


## 松手后自动引导校正（0.57）

每次画线 / 拖端点从 pointerdown 开始画布事务，pointerup 完成源图映射；有足够方向约束时立即提交独立求解进程，成功后将参数和引导线作为同一历史条目写入文档并刷新预览，工具保持开启。一次操作只增加一条撤销记录。第一条线、1H+1V 或删除后少于两条同向线时仅保存引导线，保留当前透视设置；重置透视仍通过独立控件操作。完成按钮仅退出，不另写历史。

每次成功更新后等待新 revision 的预览再准备下一次操作，重新映射源图引导线。失败时活动文档不变，待修正的线保留，可拖动、删除或重试；失败草稿和求解等待均保持保存 / 导出 / 退出保护。Esc 或切换工具取消未完成的操作，之前成功的编辑保留；切换图片或改参数后丢弃迟到结果。没有历史的撤销键为空操作，不再使当前画布事务无故失效。 打开 / 切换文档已显式显影时，后续 React 更新不再为相同对象、参数引用、配置版本与预览标志安排冗余刷新；快速关闭再打开覆盖层也可复用已有原生覆盖图。

## Adobe CRS 标准字段扩展（当前工作区 / 引擎 24）

当前工作区将以下已有 ART 处理参数提升为 Camera Raw `crs` 标量属性：`Exposure2012`、`Temperature`、`Tint`、`Contrast2012`、`Highlights2012`、`Shadows2012`、`Whites2012`、`Blacks2012`、`Vibrance`、`Saturation`、`Texture`、`Clarity2012`、`Dehaze`、`PostCropVignetteAmount`、`GrainAmount`、`Sharpness`、`SharpenRadius`、`LuminanceSmoothing`、`ColorNoiseReduction`、`LensManualDistortionAmount`、`VignetteAmount`。手动镜头扭曲将 Adobe `-100..100` 映射到 ART `-0.5..0.5`；镜头暗角使用 `-100..100` 直接驱动 ART 的 RAW 域暗角校正。`SharpenDetail` 0–100 映射 ART USM contrast 0–80；`SharpenEdgeMasking` 启用双边 edge-only 路径，并把 0–100 映射到 10–10000 容差，这两项是近似语义。`LuminanceNoiseReductionDetail` 直接映射 ART denoise detail，`LuminanceNoiseReductionContrast` 映射 detail threshold；`ColorNoiseReductionDetail` 和 `ColorNoiseReductionSmoothness` 组合映射 guided chroma radius，属于近似语义。`PostCropVignetteFeather` 与 `PostCropVignetteRoundness` 直接映射 ART 裁切后晕影，范围分别为 0–100 和 −100–100。`DefringePurple/GreenAmount` 与各自 `HueLo` / `HueHi` 作为完整组输入，按线性三角窗构造成 ART flat hue curve，并在 Lab 色差边缘阶段执行；这是本地算法近似，不是 Adobe 实现。`RedHue`、`RedSaturation`、`GreenHue`、`GreenSaturation`、`BlueHue`、`BlueSaturation` 直接映射 ART `PRIMARIES_CHROMA` 的 hue / saturation tweak，单位为同一 −100..100 控件尺度。另将四条 PV2012 点曲线、`ParametricShadows` / `ParametricDarks` / `ParametricLights` / `ParametricHighlights` 与三个分界、八色 Hue / Saturation / Luminance 共 24 个 HSL 属性、`ColorGrade*` 四轮色相 / 饱和度 / 明度、混合和平衡共 14 个属性写入标准字段。几何保存使用 `tiff:Orientation`、`HasCrop`、`CropTop` / `CropLeft` / `CropBottom` / `CropRight` 和 `CropAngle`；90° 旋转在标准侧车坐标与内部未旋转坐标之间双向转换。保存时这些字段或完整组从 `ARTAdjustments` 删除，避免同一参数同时存在标准属性和私有副本；ART 独有的蒙版、透视、配置文件引用等继续使用带类型 RDF 扩展。

读取范围按当前 ART 核心的真实能力校验：整数控制拒绝小数，滑杆范围外的值在进入显影前拒绝，不静默夹值。无 CaptRAW 引擎标记的 Adobe 预设只把文件中出现的字段应用到目标，不制造缺省值。引擎 20–23 的私有控制值继续保留；旧版本中同时存在标准属性和私有值的文档由私有值维持既有像素，下一次保存迁移到标准属性。镜像 TIFF Orientation 尚未映射时不应用对应裁切并明确提示。字符串、限定符、嵌套蒙版和未知属性仍由官方 XMP Toolkit 原样保留。

字段归属提升到引擎 24，旧 0.57 / 引擎 22 和引擎 23 候选会拒绝新文档，避免把标准字段误当成未知属性；当前版本继续读取 20–23。50 项 XMP 专项覆盖 21 个基础标量、6 个校准、2 个锐化细分、4 个降噪细分、2 个裁切后晕影形状、7 个参数曲线、24 个 HSL、14 个颜色分级、9 个黑白、6 个色差去边和 7 个裁切 / 旋转字段的导入、范围校验、标准保存、不完整组拒绝、无私有重复、旧版迁移、未知字段保留和真实 TIFF 像素响应。另以只读方式导入六份本机 ACR 侧车，源哈希不变；这不证明 Adobe 的自动算法、交互或最终画质相同。

## 按相机设置匹配曝光（当前工作区）

原生 `open` 响应新增可选 `exposureCompensation`，取自 ART 元数据的 `ExposureBiasValue`。共享契约以 `log2(N² / t) - log2(ISO / 100) - exposureCompensation` 计算拍摄 EV；目标照片的新曝光值为“目标当前编辑曝光 + 来源 EV − 目标 EV”，量化到 0.01 EV。主动照片保持不变，计算在提交前完成，任一目标缺少元数据或结果超出 ART `-5..+5 EV` 时拒绝整批操作，不静默夹值。

桌面为每个发生变化的候选目标用独立同步工作进程生成真实预览，成功后一次性更新所有目标调整、ART 配置、缩略图、脏标记和各自撤销历史；任一后台处理或预览读取失败都不提交已完成的候选。当前只实现 ACR 18.7 的“按相机设置”，没有场景光线分析、同场景确认或 Adobe 数值 / 画质等效声明。

## 本地自动影调（当前工作区）

固定 ART 的 AutoExp listener 没有可调用的实际计算回调，因此 UI 的“自动”直接消费当前预览的 3×256 RGB 直方图。亮度按 Rec.709 系数合成，读取 1% / 10% / 20% / 50% / 80% / 95% / 99% 分位；曝光向 45% 中位亮度偏移，对比度、高光、阴影、白色和黑色按分位展开与裁剪程度计算有界增量。结果叠加在当前六项影调上，一次点击只形成一步撤销。

该算法完全本地、可测试且不依赖场景识别，但不模拟 ACR Auto 的对象、内容或自适应策略，不能按相同照片宣称同值、同色或同画质。

## 直方图裁剪警告（当前工作区）

直方图左右三角分别切换阴影与高光覆盖。前端从当前 sRGB 适屏预览读取像素：阴影要求三通道均不高于 3，高光要求任一分量不低于 252；阴影标记为蓝色，高光标记为红色。生成的离屏覆盖层只在裁剪警告、源预览或 1:1 详细区域变化时重算，随后随现有图像变换缩放和平移，并在 1:1 时使用对应的原生详细区域。

该状态只用于当前显示，不进入 RAW、ART 配置、XMP、撤销历史或输出；前后对比开启时关闭警告，避免把参考和当前像素混在同一覆盖层。阈值为 CaptRAW 明确的显示规则，尚未证明与 ACR 内部警告阈值和颜色矩阵完全一致。

这实现了完成参考线后自动变换；尚未实现按住端点拖动期间连续求解。仍沿用独立 CPU 进程的解码 / 预览 / 拟合路径，45 MP 交互性能和 ACR 18.7 手感同级需要单独测量。没有更改核心、显影版本、几何坐标约定或 XMP 模式。


## Adobe XMP 蒙版导入（0.59）

`decodeAdobeMaskGroups()` 将 `crs:MaskGroupBasedCorrections` 的 RDF Seq 投影为已有 `LocalMask` / 组件。读取启用组与启用组件，保留名称与同步 ID；`MaskBlendMode` 0 / 1 / 2 对应添加 / 减去 / 相交，首组件按添加初始化。没有可用组件的组不创建。原始 Adobe 结构仍保存在 XMP 元数据图中；编辑后的 CaptRAW 蒙版保存于已有 RDF 扩展，不反写为完整 Adobe 蒙版。若两者并存，恢复 CaptRAW 私有蒙版并提示，避免旧 Adobe 结构覆盖后续编辑。

- `Mask/Gradient`：FullX/Y → 起点、ZeroX/Y → 终点；按当前原图归一化坐标导入。
- `Mask/CircularGradient`：Left / Top / Right / Bottom → 径向边界，组合 Flipped 与 MaskInverted，读取 Feather；缺少 Version 的旧形状使用半量羽化。旋转角度尚未实现，按边界框近似且明确警告。
- `Mask/Paint`：读取 Dabs 与 Radius，转换为当前画笔点；原始笔压、流量与笔尖行为尚未等效。
- `Mask/RangeMask`：仅 Type=2，LumRange 的四个 0–1 阈值转换为 0–100；组合范围反选，非法次序明确拒绝。颜色与深度范围目前跳过并提示。

`LocalExposure2012` ×4 映射为 EV；局部曝光原生限制与 UI 同步扩大至 ±4。已接入的对比度、饱和度、高光 / 阴影 / 白色 / 黑色、局部温度 / 色调、色相、纹理、清晰度与亮度降噪按当前字段缩放，CorrectionAmount 乘于这些数值。超出当前范围时夹紧并提示。它们驱动既有 ART 模块，未证明与 ACR 相同数值对应相同像素。

`Mask/Image` 的主体 / 天空 / 人物仅有引用，尚不能由 XMP 重建选区。局部去朦胧、锐化、摩尔纹、去边、颗粒、染色及非默认曲线饱和度细化没有等价控件，非中性值提示未应用。旧版 `GradientBasedCorrections`、`CircularGradientBasedCorrections`、`PaintBasedCorrections` 容器仍未接入。混合组中的未支持组件可能被跳过，导入结果须结合警告检查，不能视为原 Adobe 选区等效。

处理版本仍为 24 / 基线 4，沿用原有蒙版存储及 ART 输出。`tests/xmp-mask-import.mjs` 使用构造 XMP 核查字段、实际覆盖方向、像素变化和保留原结构；`tests/xmp-mask-import-e2e.mjs` 在隐藏安装版中执行导入、编辑、保存、新进程恢复和 TIFF16 / ICC，并与独立核心输出逐像素比较。两者使用独立临时目录，成功后仅保留检查记录与最终截图，失败保留工作目录。尚无真实 ACR 蒙版侧车的边界或质量验收。


## Adobe 蒙版组完整性与删空恢复（0.60）

0.59 在读取失败的 AI 基础组件后继续导入剩余渐变，并将首个减去组件改成添加。这会把“人物减去渐变”改成错误区域；本机 ACR 18.7 `Defaults/Previous.xmp` 只读复现：5 组中错误导入了 2 个线性组。0.60 不再改写组件运算；任一组件未能读取时整组不参与显影，原 Adobe 结构保留，界面明确提示整组未应用。旋转径向也不再用无旋转边界框代替。非法 MaskBlendMode 明确拒绝；组和可读取组件的启用 / 停用状态保持。

保存的 CaptRAW `masks` 字段以是否存在判定优先级，空数组也是明确的编辑结果。已删除全部蒙版时跳过原 Adobe 蒙版投影，保留原 ACR 元数据结构；重开不再复活旧选区。没有私有字段的纯 Adobe 文件仍正常导入。此调整沿用引擎 24 和现有 RDF 扩展，没有增加旧 JSON 格式。

画笔读取标准 RDF Seq 的 `Dabs`：`d x y` 记录落笔坐标，`r radius` 改变后续点的半径；保留逐点半径及当前擦除语义。未知指令、没有落笔点或非数组数据不会被猜成坐标对，而是披露整组未应用；非法坐标 / 非有限数值明确拒绝。笔尖、半径单位、流量、笔压及羽化仍采用现有 ART 近似，界面告知尚无 ACR 边界等效证明。结构依据为 [ExifTool 作者维护的 CorrectionMask 数据模型](https://github.com/exiftool/exiftool/blob/master/lib/Image/ExifTool/XMP.pm)；不将 RDF 解析通过等同于笔触渲染等效。

`tests/xmp-mask-import.mjs` 可通过 `CAPTRAW_ADOBE_MASK_REFERENCE` 指定本机真实 ACR 设置 XMP，只读核查 AI 组合不会被残缺导入，并记录版本、组数和源文件校验值，不分发参考文件。原生专项还验证删空后的中性像素、组 / 组件停用状态、非法运算与未知画笔指令。隐藏 GUI 从可见删除按钮逐个删除四组、撤销重做、保存并在新进程恢复空列表，验证原始结构仍保留且显示像素一致。


## 颜色分级标准字段纠正（0.61 / 引擎 25）

0.58–0.60 将五个自拟名称误当作 Adobe 标准字段，造成自有往返测试通过、真实 ACR 分级却被判为不完整。0.61 改用本机 ACR 18.7 设置及 [ExifTool 原始 CRS 数据模型](https://github.com/exiftool/exiftool/blob/master/lib/Image/ExifTool/XMP.pm)共同确认的 14 项：

| 控制 | Adobe XMP 字段 |
|---|---|
| 阴影色相 / 饱和度 / 明度 | `SplitToningShadowHue` / `SplitToningShadowSaturation` / `ColorGradeShadowLum` |
| 中间调色相 / 饱和度 / 明度 | `ColorGradeMidtoneHue` / `ColorGradeMidtoneSat` / `ColorGradeMidtoneLum` |
| 高光色相 / 饱和度 / 明度 | `SplitToningHighlightHue` / `SplitToningHighlightSaturation` / `ColorGradeHighlightLum` |
| 全局色相 / 饱和度 / 明度 | `ColorGradeGlobalHue` / `ColorGradeGlobalSat` / `ColorGradeGlobalLum` |
| 混合 / 平衡 | `ColorGradeBlending` / `SplitToningBalance` |

0.61 读取和写出使用同一标准表，当时要求完整 14 项；0.62 的稀疏合并和旧式转换已替代该限制，见下节。数值仍驱动现有 ART 后置分级适配，不表示 Adobe 算法或相同数值的像素等效。

旧 CaptRAW 版本 24 的 `ColorGradeShadowHue/ShadowSat`、`ColorGradeHighlightHue/HighlightSat` 与 `ColorGradeBalance` 在有自有版本标记时读取为旧编辑值；即使同时存在旧 Adobe 源文件遗留的不同数值，也优先保留 CaptRAW 当时保存的参数并提示。文档与预设保存先通过 SDK 读取原元数据图，只对版本 24 的旧自有字段执行移除，再写正确字段。没有旧自有标记的同名未知属性保持原样。

新文档写入 `CaptRAW-25_ART-1.26.10_LibRaw-3b20539`，读取 20–25；原生就绪消息也修正为 25。版本 25 不把外来未知同名属性解释成旧 CaptRAW 值，避免导入、保存后再打开时意外覆盖标准参数。版本 24 安装版明确拒绝新文件；旧 XMP 原文件不自动改写，原 JSON 格式没有恢复。原生显影改动仅为就绪版本字符串，分级处理和 ARP 参数语义保持。

另将已处理的 `HasCrop`、`CropTop/Left/Bottom/Right` 与 `CropAngle` 纳入已识别字段，避免保存后仍误报未参与显影；不完整 / 无效裁切仍按原有规则处理。

验证入口为 `tests/xmp-color-grading.mjs` 与 `tests/xmp-color-grading-e2e.mjs`，使用独立临时目录。前者核查实际 14 字段、旧名称冲突 / 迁移、未知字段保留、缺失 / 非法参数、预设及与旧安装核心的 TIFF16；可通过 `CAPTRAW_ADOBE_MASK_REFERENCE` / `CAPTRAW_ADOBE_GRADING_PRESET` 只读核对本机真实设置 / 预设。后者从可见控件导入、编辑、撤销、保存重启、预设和输出，并可用 `CAPTRAW_GRADING_PREVIOUS_APP` 验证旧安装版的明确拒绝。真实 Adobe 文件不分发，成功后清理临时图片及旁车。


## 稀疏 XMP 与旧式分离色调（0.62 / 引擎 26）

`AdjustmentPatch` 区分“未指定”与“显式零值”。HSL 的任意颜色 / 通道、参数曲线的任意亮度区及分界、分级的任意轮 / 分量 / 混合 / 平衡、六个原色校准值均按字段与目标当前设置合并。稀疏索引以对象穿过 JSON Lines，避免数组空位变为 null。预设仅保存指定字段，不把目标值或导入验证用的中性设置写回文件。应用后保存照片则写已解析的完整编辑。

带 `ARTProfile` 的稀疏文档先调用 `adjustmentBase` 投影原配置，避免用新照片默认值覆盖未指定部分。HSL 只接受标准八色位置、零切线且能无损表达为整数控件的曲线；自定义形状拒绝载入。参数曲线只接受当前原生参数格式和可无损还原的整数分界；校准只接受启用的 PRIMARIES_CHROMA 或停用状态，其他通道混合模式明确拒绝。该只读接口不更改处理算法或原始配置。

三个参数分界遵循当前引擎的整数 1–99 范围，至少相隔 1。导入时检查已指定分界的可行性，缺项留到目标照片合并后检查。例如仅含 ShadowSplit=60 的预设可以导入；目标 MidtoneSplit=58 时应用失败，=74 时可以应用。失败不会提交部分调整。

五个 `SplitToning*` 全部出现且没有现代 `ColorGrade*` 字段时，按 [Adobe 官方兼容规则](https://blog.adobe.com/en/publish/2020/10/20/introducing-color-grading)将混合设为 100，中间调 / 全局 / 所有明度设为零。该形状识别为本项目推断，不将只有部分旧字段的现代预设默认化。首次导入返回的说明在预设面板显示，标准化保存后不依赖原五项缺省结构。真实 Adobe 文件只读核验，不进入源码 / 安装包。

文档和预设版本为 `CaptRAW-26_ART-1.26.10_LibRaw-3b20539`，读取 20–26；0.61 会明确拒绝新版本，避免误读稀疏预设。原 JSON 格式仍不读取或迁移。测试入口为 `tests/xmp-partial.mjs` 和 `tests/xmp-partial-e2e.mjs`；后者只使用隐藏、不可聚焦的真实 Electron 窗口，从可见控件操作并检查实际像素、保存恢复和 TIFF16 / ICC。不能据此宣称 Adobe 色彩、曲线采样或画质等效。
